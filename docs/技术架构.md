# OpenSource Scout Agent 系统架构

版本：2.0｜2026-10-29｜状态：待实现。以当前PRD和DECISIONS为准。

## 1. 技术选型

| 层 | 选择 | 原因 |
|---|---|---|
| 前端 | Vue 3 + TypeScript + Vite | 浏览器交互；本机/CI构建静态文件 |
| 后端 | Node.js受支持LTS + TypeScript + Fastify | 前后端统一语言；单进程API与静态文件服务 |
| 持久化 | SQLite，WAL，本地磁盘 | 无独立数据库服务；短事务 |
| 数据访问 | better-sqlite3 + 版本化SQL迁移，兼容性实测后锁版本 | 简单访问；不引入大型ORM；限制同步查询规模 |
| 输入/输出校验 | JSON Schema + Fastify校验，模型输出同样校验 | TypeScript类型不替代运行时校验 |
| 模型 | 单供应商SDK或fetch薄适配 | 在线API；结构化输出、超时、用量记录 |
| 流程 | 普通TypeScript步骤函数 + SQLite状态 | 不引入LangGraph、Agent框架或Checkpointer |
| 任务 | 进程内单执行器 + 持久任务表 | 不引入Redis、独立Worker、Scheduler |
| 日志 | Fastify/Pino结构化日志与脱敏 | 限制内容与文件保留 |
| 部署 | 单Node应用服务，由systemd管理；HTTPS反向代理 | 不常驻Vite、tsc、开发服务器、Node集群 |

具体Node与依赖版本在实施时验证并锁定。后端预先编译JS；服务器不负责常规构建。初期不需要Nuxt/SSR、Python运行时、向量库或本地模型。2GB是容量目标，不凭框架名宣称实测占用。

## 2. 部署结构

```text
浏览器（Vue静态页面）
        ↓ HTTPS
反向代理（TLS）
        ↓ 本机监听
一个Node/Fastify进程
  ├─ Vue静态文件
  ├─ 登录、管理API、公开投影API
  ├─ 单任务执行器 → GitHub只读API / 模型API
  └─ SQLite + 私有报告/补丁文件
```

反向代理是轻量部署依赖，初期不需要额外容器平台；如采用Compose须提供等价的单应用部署，不引入多套默认方案。用户本机只需浏览器。执行器只是同进程业务模块，不另起常驻Worker；不执行第三方构建、Git hooks、安装或测试。

## 3. 模块与步骤

建议目录：frontend/、server/{api,auth,db,github,model,tasks,reports,publication}、migrations/、tests/、docs/。普通模块隔离职责，不拆微服务。

输入 → Issue快照 → 选择Commit → 有界源码文本获取 → 模型分析 → 保存计划并等待确认 → 模型生成Diff → 非执行性检查 → 供人工审核下载。

不调用任意Shell；优先使用GitHub API获取文本，不克隆整仓和创建Worktree。远端请求有超时、响应大小限制及有限网络重试。源码及Diff仅作为不可信文本处理。

## 4. 最小数据模型

| 表 | 内容 |
|---|---|
| settings | 模型、限额、只读凭据引用；不存明文secret |
| tasks | repo、Issue、base_sha、配置快照、状态、当前步骤、错误、时间 |
| task_steps | 输入摘要/hash、步骤版本、输出引用、实际状态和耗时 |
| plans | 版本、目标Commit、允许路径、计划hash、确认时间 |
| artifacts | 分析、Diff、PR文案、hash、大小及私有存储键 |
| usage | 任务/调用、预留Token、已知usage、未知用量标记 |
| publications | 审核后的白名单快照、公开ID、发布时间、撤回时间 |
| manual_pr_records | 所有者输入的链接/状态、来源MANUAL、更新时间 |
| sessions | 有效期、会话标识hash；不得保存原始会话令牌 |

迁移用有序SQL与schema版本记录。配置只保存所需快照和secret引用；任务重试默认复用快照。源码Commit或计划变化则新修订分析，不混用旧补丁。

## 5. 简化任务生命周期

QUEUED → RUNNING → WAITING_CONFIRMATION → QUEUED → RUNNING → COMPLETED。

运行也可进入FAILED、CANCELLED；进程重启将遗留RUNNING标为INTERRUPTED，只有所有者显式重试才入队。不承诺透明Checkpoint恢复或外部调用恰好一次。步骤完成先保存不可变输出，再提交状态，失败遗留文件可后续清理。

只支持一个应用实例；原子领取与状态条件更新、提交请求幂等键、单执行器防重复即可，不实现分布式租约。等待确认不阻塞其他任务。取消时中止可取消请求，拒绝迟到结果覆盖已取消/已重试的任务；使用attempt版本检查，不需跨进程fencing。模型调用超时可能已计费，提示后再手动重试。

## 6. 2GB资源控制

- 一个Node进程、一个活动任务；网络请求有小型并发上限。
- 源码限制文件数、单文件/总大小、上下文；禁止无界整仓分析。
- SQLite短事务，网络/模型调用在事务外；分页查询，避免同步大查询阻塞事件循环。
- 模型调用前预留Token与调用额度；未知usage保守保留占用，不记作0；超限暂停。
- 制品原子写入、大小上限、日志轮转、缓存清理；备份覆盖数据库与引用制品。
- 内存、并发、文件数等数值作为配置，M0记录基线，M1—M3实测后调整。
- 禁止在Web进程执行CPU密集第三方工具。若未来需要，单独设计受限执行环境。

## 7. 安全与公开边界

单管理员，密码hash、HttpOnly/Secure/SameSite会话Cookie、有效期、登录限速；基于Cookie的变更请求验证CSRF/Origin。管理API强制鉴权，监听仅经HTTPS代理访问。

只解析受支持GitHub URL为owner/repo/number，再调用固定GitHub端点；不提供任意URL代理。限制重定向、响应大小、超时和私有网络访问。URL及密钥不得直接拼成Shell。

凭据由环境/私有配置引用，不送模型，不写制品和公开数据；目录权限隔离。Diff路径拒绝绝对路径、上级跳转和超范围变更；不直接应用到服务器文件系统。公开端只读独立发布快照，不能按内部文件路径下载。Markdown禁用不安全HTML并安全处理链接。

步骤摘要记录可观察事实，不保存或公开隐藏思维链。发布前预览并人工确认，撤回立即阻止新读取，不公开未经审核的原始日志。

## 8. 验证与运维

测试重点：鉴权、输入校验、状态/重复提交、取消迟到结果、计划hash与范围、限额、脱敏、发布撤回。GitHub/模型先用标记夹具验证，再用真实只读调用留证；目标项目测试明确NOT_RUN。

健康检查区分进程与数据库。systemd重启不自动重放中断任务。备份需使用SQLite一致性备份及制品清单，恢复校验引用hash。报告空闲、分析峰值及补丁生成峰值RSS/整机可用内存；未测不填假数据。
