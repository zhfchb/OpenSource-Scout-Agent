# M5：轻量自动发现与候选管理

版本：2.2｜实施更新：2026-10-30。M5 工程与夹具/浏览器验证完成，真实立即发现与来源复核已有结果；正常定时遇 GitHub 限流，成功结果待补。未调用真实付费模型、未部署。实际编码与差异见 [使用说明](M5使用说明.md) 和 [验收记录](../evidence/M5/验收记录.md)。

## 1. 产品边界与当前基础

核心流程：技术画像 → 手动/定时发现 → GitHub 查询和规则初筛 → 可选少量模型评估 → 私有候选列表 → 人工选择 → 状态复核 → 现有深入分析/确认计划/待验证补丁/审核下载。候选只表示可能值得贡献，完整贡献仍需系统外验证和提交。

M5 已增量实现 discovery/profile/routes/github-budget/work-queue 等模块及迁移 006；复用原任务执行器和执行槽，有持久画像、调度、候选、水位、预算、冷却与前置复核。传输层仅暴露白名单状态/限流元信息，不保存原始响应头。M4 配置诊断与模型探测已本地实现；真实付费闭环未验收，见 M4 使用说明与证据。

发现阶段只读取公开仓库元信息、Issue 有界摘要和必要状态信息，不读取源码树/blob，不 clone/fork，不运行目标代码，不自动创建分析或补丁。全部应用逻辑在既有单 Node 进程；SQLite 为持久事实来源，定时器只唤醒执行器，无独立 Scheduler/Worker 服务。

## 2. 技术画像与默认筛选

首期支持一个可版本化活动画像，浏览器编辑；不构建多画像路由或复杂评分。字段有运行时长度/数量/枚举校验；查询由服务端从结构化字段编译，不开放任意查询 URL 或任意端点。

| 字段 | 初始默认与语义 |
|---|---|
| 语言 | Java、Python，可增删；至少一项，最多 5 项；按仓库语言元信息匹配，不推断用户精通程度 |
| 偏好标签 | good first issue、help wanted；任一匹配优先显示，也可配置“必须匹配”；默认偏好而非硬过滤 |
| 排除标签 | 默认空；最多 20 项；命中任一即过滤 |
| 活跃度 | 仓库最近 push 不超过 180 天；Issue 最近更新不超过 90 天；说明 push 时间不等于维护者响应能力 |
| 规模偏好 | 默认 star 20–20000，可关闭或调整；仅作公开规模代理，不等于代码量/复杂度 |
| 仓库限制 | 默认排除 private、archived、disabled、fork；排除仓库最多 200 个，按稳定 ID 匹配，名称作为首次解析入口 |
| Issue 规则 | open、非 PR；默认不强制无人认领，展示 assignee；排除已忽略/已进入分析候选 |
| 模型评估 | 默认关闭；开启前显示可能持续计费并确认，记录启用者/时间/版本，定时发现也受同一明确配置约束 |
| 定时发现 | 初始未启用，首次保存画像后可明确启用；默认每日一次，时间为 UTC 02:00（北京时间 10:00） |

定时仅支持每日一个 UTC 时刻（整点，0–23），可关闭；不引入 cron 表达式或复杂时区计算。页面同时显示 UTC 和北京时间。立即发现不要求定时已开启，也不要求配置模型；无有效画像不运行。模型未配置/预算不足时，规则候选照常可用，模型评价标 NOT_RUN 并说明原因。

保存画像递增 revision；运行保存不可变画像、规则版本、模型/限额快照。新配置只作用后续扫描；历史匹配理由标出版本，新发现不能覆盖收藏/忽略状态。编辑时带 expectedRevision，冲突拒绝覆盖。排除仓库、忽略候选、关闭模型评估、关闭定时是即时收紧控制：执行器在下一次网络/模型调用及写入推荐前检查当前控制，不因旧快照继续付费或推荐已排除项；已发起调用只能尝试取消并保留用量。

## 3. 有界查询、规则与推荐理由

先按语言/活跃度/规模搜索仓库，再在有限仓库内查询开放 Issue；标签偏好用于排序，不能在默认偏好模式下只搜索该标签而漏掉其他候选。服务端生成固定数量查询分片，每轮最多 5 个，不跟随远端任意 next URL；固定 api.github.com，只读 GET。具体搜索参数/权限、分页和时间字段语义在实施时核对 GitHub 官方文档与真实响应，不能声称搜索完整或实时一致。

规则按公开性/排除项 → 活跃度/规模 → Issue 类型/状态/标签 → 去重/人工偏好顺序执行。保存匹配字段、过滤原因和查询来源，不强制加权总分。默认列表排序：收藏优先、偏好标签命中优先、最近 Issue 更新时间降序、稳定 ID 打破同值；旧画像结果标“需重新匹配”。查询/分页受限的轮次显示“不完整”，不把未返回解释为不适合或已关闭。

候选卡片显示仓库、Issue 标题/编号、稳定来源链接、匹配理由、疑点、规则/模型来源、首次/最近发现、最后状态检查时间。匹配事实与模型意见分栏；语言/标签匹配不能表述为“确定适合你”。模型只接收画像和最多 4KiB 的 Issue 文本摘要/必要元信息，最多输出 512 Token 的推荐理由、疑点与建议，不访问源码、不授予工具权限，不覆盖确定性硬过滤。

## 4. 去重、增量与遗漏语义

仓库以 GitHub repository ID 去重，Issue 以稳定 issue ID 去重，名称和 number 是可变化的显示/定位字段；Issue 转移/仓库重命名后用稳定 ID 更新映射，不能直接信任远端 URL 或另建重复候选。API 未返回必要稳定标识时拒绝持久化该条并计入缺口。来源记录查询摘要/hash、run、画像版本、远端 updated 时间和读取时间；不保存带凭据的请求 URL。

持久游标按“画像查询 fingerprint + 仓库 ID/查询分片”隔离，记录扫描窗口、上次成功水位、页位置/截断原因。首次只扫最近 90 天更新的开放 Issue；后续成功窗口从水位向前重叠 48 小时去重。模型/调度参数调整不必清空查询游标，语言/标签硬条件/活跃度等查询改变则新建 fingerprint，不复用旧查询水位。

同页候选 upsert、来源摘要和页进度在事务中提交。只有该固定窗口在限额内完整结束才推进成功水位；限流、页上限、取消、超时或 incomplete 标志保留旧水位并记 PARTIAL。下轮允许重读重叠页，不盲目续用可能漂移的 page offset。不补扫无限历史，不为追平而无限翻页；持续截断提示缩小画像/增加查询分片（仍受总上限约束）。定期轮换有限仓库片段，不能声称已经遍历全部仓库或保证不会遗漏。新查询窗口与重叠也不能消除 GitHub 搜索延迟、结果上限或排序漂移。

## 5. 人工候选管理与进入分析

候选人工偏好与远端状态分开：visibility 为 ACTIVE/IGNORED，favorite 为独立布尔，分析选择/任务状态存关联表；远端状态 OPEN/CLOSED/UNKNOWN，过期另用 needsRecheck 标志。忽略是持久 tombstone，重扫只更新必要来源/远端时间，不恢复推荐；从“已忽略”列表点“重新启用”转 ACTIVE，原收藏不丢。收藏切换不取消忽略，默认推荐仍排除已忽略项。进入分析保留 favorite，不再默认推荐已有分析关联的候选；分析失败可从候选详情显式重试原任务，或确认新费用后新建分析，禁止扫描自动重建。取消仓库排除后也不恢复忽略项；在库候选重新匹配/复核后才推荐。忽略/排除不自动取消已有分析，页面提示须另行取消任务。

“进入分析”是人工触发的幂等动作：requestKey + candidate ID + 当前画像版本；重复提交复用同一请求，已有活动分析返回其入口。先持久化选择/复核记录，以 SOURCE_RECHECK 工作项进入同一队列，不立即并行访问 GitHub；这一元信息复核不要求模型配置，不直接调用当前 TaskService.create 的模型前置校验。领取槽后刷新公开仓库、Issue open 状态及身份，尽可能读取有限关联关闭/交叉引用事件、关联 PR 状态；关联 URL 只解析成受支持 GitHub 标识后调用固定 API，不跟随任意链接。初始最多 2 页、每页 20 条关联事件，最多核查 3 个关联 PR，所有请求受总额度约束。

关闭/已合并且可确认关联修复时停止付费分析，提示查看来源；存在开放关联 PR 时显示可能重复，让用户确认是否继续；无法读取、无足够权限、截断或关联不明确显示 UNKNOWN，不能说“没有重复 PR”。即使未发现关联，也显示“本次有界检查未发现，不能排除重复修复”。用户在当前复核结果 hash 上明确确认风险后才可深入分析。

复核记录可进入 WAITING_SOURCE_CONFIRMATION，等待释放槽、不调用模型；页面“开始深入分析”需有效模型/预算，并在同一选择动作下幂等调用原任务创建流程。M5 给新关联任务增加前置复核检查及必要的 WAITING_SOURCE_CONFIRMATION 分支，原 M0–M4 任务与事实保留；缺少模型时仍可完成元信息复核，不生成虚假分析。

风险确认绑定候选/复核 hash，5 分钟有效。hash 包含稳定 repo/Issue ID、公开/归档状态、Issue state/updated_at/标题与正文 hash、assignee、关联 PR ID/state/merged/updated_at、检查完整性/UNKNOWN 原因；不包含每次读取时间以免无变化也失效。重新领取槽过期则重查并再确认。源码前重新获取 Issue/Commit并比对上述字段；关联风险在确认后可能变化，付费前需重新进行相同有界关联检查。任一风险字段/hash 变化均清除确认并进入等待分支，关闭/可确认修复则停止，不持槽等人。远端多请求非原子仍存在竞态，记录读取时间与限制；候选选择/风险确认不等于计划确认，更不触发补丁。

## 6. 调度、单执行槽与恢复

每 60 秒检查 SQLite 中 enabled、scheduleRevision、nextDueAt；事务内用唯一 `(profileId, scheduleRevision, dueAt)` 消费调度触发。手动发现使用 requestKey 幂等。每实例最多一个 QUEUED/RUNNING 发现轮次；手动与定时碰撞返回现有轮次，记录触发来源而非另建重复扫描。队列满时消费该次到期并记 SKIPPED_QUEUE_FULL，不不断重试入队；已有发现占用时记 SKIPPED_ACTIVE，推进到下一个未来时刻。

复用现有执行器并扩展持久 work item 类型 DISCOVERY/SOURCE_RECHECK/ANALYSIS/PATCH；统一 FIFO，队列合计最多 10 项，只有一个活动槽。发现整轮最长 5 分钟，网络并发 1，完成/超限/取消/限流立即释放；不在槽内长时间 sleep 等限流重置。分析等待时间可受该有界轮次影响，页面显示队列。M4 模型探测仍不排队：有活动或待执行工作时拒绝，探测运行时其他任务可入队。调度 tick 和查询列表不持有外部调用槽，定时器不直接发网络请求。

重启把未完成发现 QUEUED/RUNNING 标 INTERRUPTED，未结模型账本 UNKNOWN，不重放任何模型调用。错过时刻全部跳过，不补跑历史；计算下一个未来时刻，记“错过调度已跳过”及数量/时间区间，不为每个错过时刻创建大量记录。下次正常调度可开始新的规则扫描，但相同“候选 ID + 内容 hash + 画像评估 fingerprint + 模型配置版本”的已发起评估，不论 SUCCEEDED、FAILED、CANCELLED、INTERRUPTED 或 UNKNOWN，均不自动再次调用（包括已知 usage 的不合法输出）。发送前持久写入 dispatch 标志；发送与写入间中断也按可能已发送处理。只有用户明确确认重新评估才新增 attempt，仍受预算限制；尚未预留/发起的预算拒绝不算已调用。

手动取消先更新状态/attempt，再 Abort；已提交候选/进度保留并标本轮部分完成，迟到结果不覆盖偏好/状态；可能已付费用量仍记原调用。取消当前轮次不关闭未来调度，按钮明确区分“取消本轮”和“关闭定时”。修改调度时间重新计算下一个未来时刻，取消旧 scheduleRevision 的排队项；运行项按即时收紧规则处理，不能产生第二活动轮次。

数据库从备份恢复时发现调度强制 disabled、未完成项 INTERRUPTED；所有者核对旧水位和排除/忽略项后才能重新启用。不从旧备份自动触发付费评估。恢复后至下个 UTC 日禁用发现模型评估，沿用 M4 的持久恢复 guard 并扩展用途，规则发现仍可手动运行。

## 7. 资源、网络与模型预算

以下是初始工程默认值，不是 GitHub 配额或已测容量。网页可在硬上限内调低/调高运行配置，硬上限只能服务端配置且必须有有效值。

| 限制 | 默认 | 初期硬上限 |
|---|---:|---:|
| 每轮仓库数 / Issue 读取数（过滤前计数） | 10 / 100 | 20 / 200 |
| 仓库搜索总页数 / 每仓库 Issue 页数 | 2 / 2 | 3 / 3 |
| 每页记录数 | 20 | 20 |
| 每轮发现 GitHub HTTP 尝试数（含重试） | 60 | 100 |
| 每 UTC 日发现 HTTP 尝试数 | 300 | 500 |
| 单响应 / 全轮接收字节 | 1MiB / 8MiB | 1MiB / 16MiB |
| 单请求超时 / 全轮期限 | 15 秒 / 5 分钟 | 30 秒 / 5 分钟 |
| 每轮模型评估候选数 / Token | 3 / 8000 | 5 / 16000 |
| 每 UTC 日发现模型调用数 / Token | 10 / 20000 | 20 / 40000 |
| 候选 / 来源摘要 / 轮次记录总数 | 5000 / 20000 / 1000 | 固定初期限额 |

所有限制取先到者；过滤掉的条目也消耗读取计数；请求计数在发送前持久扣减，重启不清零，跨日归预留日。进入分析的前置复核另限 10 次 HTTP 尝试/请求动作，计入共享 GitHub 冷却和现有分析流程的网络限制，不能借“发现”无限复核。

远端 primary/secondary 限流及 Retry-After/reset 只在通过验证的状态/响应头可确认时解释；403 未必限流。扩展传输层返回白名单的状态/限流元信息，不保存原始响应头/错误正文。对限流保存按 API 资源分类的 notBefore（主配额不足时同凭据共享），释放槽，后续扫描/状态复核/分析读取也遵守冷却；无可用时间时采用默认 15 分钟冷却并标原因未知。网络/5xx 最多一次短重试且计入本轮额度；限流/权限/模型不自动重试，不长占槽。远端剩余额度不足时比本地上限更早停止。

可选评估沿用单模型和凭据引用，调用前在事务内预留输入保守字节上界 + 128 + 最多 512 输出 Token；同时检查轮次和每日调用/Token，UNKNOWN 保留预留不记零。模型预算耗尽只停止评估，规则候选继续在 GitHub/时间额度内完成，轮次标 PARTIAL_EVALUATION；未配置/输出无效有固定错误与 NOT_RUN/FAILED，不编造模型理由。不新增自动付费重试或跨供应商回退。

不为发现另建常驻资源。UI 分页每页最多 20，不将全部候选加载到浏览器或 Node 内存；SQLite 索引支持稳定 ID、状态/更新时间、fingerprint/水位和预算日查询。达到存储上限暂停新增发现/评估并显示原因，保留登录、取消、忽略、撤回等控制余量；不自动删除忽略 tombstone、用量或用户收藏。按轮次/候选去重来源摘要，避免每次扫描无限追加。记录数配额与现有主库字节配额同时生效，运维显式备份/归档后才调限。

## 8. 数据与拟定接口

只新增递增 SQL 迁移，编号实施时依据当前最新版本，不覆盖 001–005；本次新增 006。旧任务无候选来源时保持手动入口语义，不伪造画像/发现记录。

| 拟新增/扩展表 | 内容与约束 |
|---|---|
| discovery_profile_versions / discovery_control | 不可变画像/规则快照；当前 revision、排除与开关、调度 revision/nextDueAt/notBefore |
| discovery_runs | trigger/requestKey/dueKey、快照、attempt、状态/部分完成原因、计数、时间与错误；唯一触发键 |
| discovery_repositories / discovery_candidates | 稳定 repo/issue ID 唯一；当前公开名称/URL标识、摘要、远端状态/检查时间、人工状态/版本 |
| discovery_sources / discovery_cursors | 候选+查询 fingerprint 来源摘要唯一；水位/窗口/完整性/页进度 |
| discovery_evaluations | 候选内容 hash/评估 fingerprint/模型版本/attempt、预留日/usage/状态；唯一逻辑评估键防重放 |
| github_request_budget / execution_queue | 持久请求尝试/日预算/冷却；统一 work item、状态、幂等键、attempt；不引入分布式租约 |
| candidate_analysis_links / source_rechecks | 选择动作幂等、现有任务引用、复核 hash/来源/UNKNOWN/确认有效期；不复用计划批准 |

如表合并可保留等价字段/唯一性，须通过相同验收，不引入通用编排平台。状态：轮次 QUEUED → RUNNING → COMPLETED/PARTIAL/FAILED/CANCELLED，重启 INTERRUPTED；API 冷却/预算不足通过 reason/notBefore 表示，不自动复活终态。用量 UNKNOWN 与轮次状态分开。

管理员接口（待实现）建议：GET/PUT `/api/admin/discovery/profile`；POST `/api/admin/discovery/runs`（requestKey/revision）；GET runs 列表/详情；POST runs/:id/cancel；GET candidates（有界筛选/分页）；POST candidates/:id/actions（ignore/enable/favorite/unfavorite/select-analysis，带预期版本/幂等键）；候选复核风险确认使用任务专属接口和 hash。全部变更鉴权、Origin/CSRF，GET 不触发扫描或模型。公开端不暴露画像、候选、调度或排除项；发布仍走原白名单快照。

备份/完整性校验覆盖全部新表、队列、游标、tombstone 和用量；恢复只改变明确声明的运行/调度/guard 字段。保存关联和 hash，不将发现元数据自动加入公开报告。客户端只轮询摘要，不访问密钥或原始网络正文。

## 9. 实施拆分与验收入口

M5-A：画像、规则、稳定标识、立即发现、候选管理、无模型 GitHub 夹具；先统一执行槽接口。M5-B：持久调度、增量、限流/预算/取消/重启、分析前复核与队列集成。M5-C：可选模型评估、M4 探测互斥、备份恢复、浏览器与真实 GitHub 只读验收。A/B 不依赖真实模型凭据或云服务器，C 的规则与真实 GitHub 证据也不要求付费模型；M4-A/B 与 M5 共用的槽/账本契约须先协调，不能各实现一套互不知情的锁。

验收覆盖 [验收与发布标准](验收与发布标准.md) 的 M5 矩阵。本地实现/夹具/浏览器已验证，真实候选及有限复核已有证据；正常定时已触发但受限流，真实成功候选、最终同窗口重复验证与可选模型/云端验收仍待补，不能标完整 M5 真实验收通过。
