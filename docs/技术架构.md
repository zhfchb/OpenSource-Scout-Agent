# OpenSource Scout Agent 系统架构

版本：2.2｜2026-10-29｜状态：M0–M3 本地已实施；M4/M5 为待实现增量。实际验证以 evidence 为准。

## 1. 技术选型

| 层 | 选择 | 原因 |
|---|---|---|
| 前端 | Vue 3 + TypeScript + Vite | 浏览器交互；本机/CI构建静态文件 |
| 后端 | Node.js受支持LTS + TypeScript + Fastify | 前后端统一语言；单进程API与静态文件服务 |
| 持久化 | SQLite，WAL，本地磁盘 | 无独立数据库服务；短事务 |
| 数据访问 | better-sqlite3 + 版本化SQL迁移，兼容性实测后锁版本 | 简单访问；不引入大型ORM；限制同步查询规模 |
| 输入/输出校验 | JSON Schema + Fastify校验，模型输出同样校验 | TypeScript类型不替代运行时校验 |
| 模型 | 单供应商SDK或fetch薄适配 | 在线API；结构化输出、超时、用量记录 |
| 流程 | 普通TypeScript步骤函数 + SQLite状态 | 不引入LangGraph、Agent框架或Checkpointer |
| 任务 | 进程内单执行器 + 持久任务表 | 不引入 Redis 或独立 Worker/Scheduler 服务；M5 在同进程定时唤醒 |
| 日志 | Fastify/Pino结构化日志与脱敏 | 限制内容与文件保留 |
| 部署 | 单Node应用服务，由systemd管理；HTTPS反向代理 | 不常驻Vite、tsc、开发服务器、Node集群 |

具体Node与依赖版本在实施时验证并锁定。后端预先编译JS；服务器不负责常规构建。初期不需要Nuxt/SSR、Python运行时、向量库或本地模型。2GB是容量目标，不凭框架名宣称实测占用。

## 2. 部署结构

```text
浏览器（Vue静态页面）
        ↓ HTTPS
反向代理（TLS）
        ↓ 本机监听
一个Node/Fastify进程
  ├─ Vue静态文件
  ├─ 登录、管理API、公开投影API
  ├─ 单任务执行器 → GitHub只读API / 模型API
  └─ SQLite（含私有来源、分析、审核包与公开快照）
```

反向代理是轻量部署依赖，初期不需要额外容器平台；如采用Compose须提供等价的单应用部署，不引入多套默认方案。用户本机只需浏览器。执行器只是同进程业务模块，不另起常驻Worker；不执行第三方构建、Git hooks、安装或测试。

## 3. 模块与步骤

建议目录：frontend/、server/{api,auth,db,github,model,tasks,reports,publication}、migrations/、tests/、docs/。普通模块隔离职责，不拆微服务。

画像 → 立即/定时有界发现 → 规则/可选模型评估 → 私有候选 → 人工选择与状态复核（M5 待实现）；保留手动输入 → Issue快照 → 选择Commit → 有界源码文本获取 → 模型分析 → 保存计划并等待确认 → 模型生成Diff → 非执行性检查 → 供人工审核下载。

不调用任意Shell；优先使用GitHub API获取文本，不克隆整仓和创建Worktree。远端请求有超时、响应大小限制及有限网络重试。源码及Diff仅作为不可信文本处理。

## 4. 最小数据模型

| 表 | 内容 |
|---|---|
| settings | 模型、限额、只读凭据引用；不存明文secret |
| tasks | repo、Issue、base_sha、配置快照、状态、当前步骤、错误、时间 |
| task_steps | 输入摘要/hash、步骤版本、输出引用、实际状态和耗时 |
| plans | 版本、目标Commit、允许路径、计划hash、确认时间 |
| artifacts | 已实施为 SQLite 内的审核包 JSON、hash、字节数与人工审核状态；来源/分析保存在任务相关记录 |
| usage | 任务/调用、预留Token、已知usage、未知用量标记 |
| publications | 审核后的白名单快照、公开ID、发布时间、撤回时间 |
| manual_pr_records | 所有者输入的链接/状态、来源MANUAL、更新时间 |
| sessions | 有效期、会话标识hash；不得保存原始会话令牌 |

迁移用有序SQL与schema版本记录。配置只保存所需快照和secret引用；任务重试默认复用快照。计划修订新建版本并重新确认；源码 Commit 改变须重新分析，不混用旧补丁。

## 5. 简化任务生命周期

QUEUED → RUNNING → WAITING_CONFIRMATION → QUEUED → RUNNING → COMPLETED。

运行也可进入FAILED、CANCELLED；进程重启将遗留QUEUED/RUNNING标为INTERRUPTED，只有所有者显式操作才入队。不承诺透明Checkpoint恢复或外部调用恰好一次。不可变结果与步骤/任务状态在 SQLite 事务内提交，不生成外部临时制品。已使用的补丁计划不重放，须保存新版本并重新确认。

只支持一个应用实例；原子领取与状态条件更新、提交请求幂等键、单执行器防重复即可，不实现分布式租约。等待确认不阻塞其他任务。取消时中止可取消请求，拒绝迟到结果覆盖已取消/已重试的任务；使用attempt版本检查，不需跨进程fencing。模型调用超时可能已计费，提示后再手动重试。实际重启处理包含 QUEUED 和 RUNNING，均转 INTERRUPTED；不只处理 RUNNING。

## 6. 2GB资源控制

- 一个Node进程、一个活动任务；网络请求有小型并发上限。
- 源码限制文件数、单文件/总大小、上下文；禁止无界整仓分析。
- SQLite短事务，网络/模型调用在事务外；分页查询，避免同步大查询阻塞事件循环。
- 模型调用前预留Token与调用额度；未知usage保守保留占用，不记作0；超限暂停。
- 审核包与快照事务写入、大小上限、日志轮转、过期会话/预览清理；备份覆盖数据库内所有内容。
- 内存、并发、文件数等数值作为配置，M0记录基线，M1—M3实测后调整。
- 禁止在Web进程执行CPU密集第三方工具。若未来需要，单独设计受限执行环境。

## 7. 安全与公开边界

单管理员，密码hash、HttpOnly/Secure/SameSite会话Cookie、有效期、登录限速；基于Cookie的变更请求验证CSRF/Origin。管理API强制鉴权，监听仅经HTTPS代理访问。

只解析受支持GitHub URL为owner/repo/number，再调用固定GitHub端点；不提供任意URL代理。限制重定向、响应大小、超时和私有网络访问。URL及密钥不得直接拼成Shell。

凭据由环境/私有配置引用，不送模型，不写制品和公开数据；目录权限隔离。Diff路径拒绝绝对路径、上级跳转和超范围变更；不直接应用到服务器文件系统。公开端只读独立发布快照，不能按内部文件路径下载。Markdown禁用不安全HTML并安全处理链接。

步骤摘要记录可观察事实，不保存或公开隐藏思维链。发布前预览并人工确认，撤回立即阻止新读取，不公开未经审核的原始日志。

## 8. 验证与运维

测试重点：鉴权、输入校验、状态/重复提交、取消迟到结果、计划hash与范围、限额、脱敏、发布撤回。GitHub/模型先用标记夹具验证，再用真实只读调用留证；目标项目测试明确NOT_RUN。

健康检查区分进程与数据库。systemd重启不自动重放中断任务。备份需使用SQLite一致性备份及制品清单，恢复校验引用hash。报告空闲、分析峰值及补丁生成峰值RSS/整机可用内存；未测不填假数据。

## 9. 已实施结构与 M4 增量

当前模块在 server/ 下平铺：app/auth/db/config、github/network/model/tasks、patch/review/publication、storage/metrics 及 backup/restore。前端在 frontend/src/，迁移为 001–004。上述建议目录不要求为了外观重构已实施代码。

当前来源、分析、审核包、公开快照都在 SQLite 中，没有独立制品目录；使用事务提交受限 JSON，不引入文件与数据库双写。备份清单核对数据库、表摘要与内容 hash；恢复默认撤回公开报告。实施细节以 M3 使用说明为准。

M4 新增模型诊断服务、受限连接探测和统一错误展示，复用固定供应商网络适配。新增 settings revision 与 model_tests 账本，诊断无网络，付费探测有单独预算但共用任务执行槽；取消、迟到结果和重启沿用 attempt 约束。探测结果永不进入公开快照。接口、数据字段、限额、恢复细节见 [M4 专项设计](M4真实模型联调设计.md)。

M4 迁移须更新备份表清单与完整性校验、旧备份恢复升级测试；迁移不填造历史探测/usage。模型设置更新只作用于新任务/探测，旧任务保持快照。任何新增公开字段必须重新设计白名单并人工预览，不直接复用管理接口返回值。

## 10. M5 发现与轻量调度增量（待实现）

新增同进程画像/查询编译、规则筛选、候选管理、发现运行和调度模块，扩展 github/network 以读取有界搜索及白名单限流元信息。发现只接触仓库元信息与 Issue 摘要，不调用现有 snapshot 的源码树/blob 路径。不存在独立 Worker、LangGraph 或多 Agent。

```text
浏览器画像/立即发现 ─┐
进程内60秒定时检查 ─┴→ SQLite持久触发/队列 → 统一单执行槽
  ├─ DISCOVERY：GitHub查询 → 规则过滤 → 可选小额模型 → 私有候选
  ├─ SOURCE_RECHECK：人工选择 → 无模型状态复核/风险确认
  ├─ ANALYSIS：有效配置与风险确认后 → 复查确认仍有效 → 原有深入分析
  ├─ PATCH：原有计划确认后单次生成
  └─ MODEL_TEST：M4主动测试，不排队；槽或队列占用时拒绝
```

执行器统一 FIFO，最多排队 10 项、最多一个待执行/活动发现轮次；发现最长 5 分钟，等待人工或限流不占槽。定时器只入队，不发网络请求；重复触发依靠事务和唯一键，单进程互斥无需分布式租约。M4 与 M5 必须复用同一槽，不能各自维护独立 running 标记而并行请求。

新增画像版本/调度控制、发现轮次、稳定仓库与候选 ID、来源/游标、评估用量、HTTP 日预算/冷却、统一队列与候选分析关联。人工偏好和远端状态分开；忽略 tombstone 跨扫描保存，配置快照不能覆盖当前即时排除/禁用控制。候选/来源/记录及网络响应均设配额，详情见 [M5 设计](M5自动发现设计.md)。

规则发现不依赖模型。发现模型评估默认关闭，显式开启后才允许定时付费；每轮/每日预算独立于任务与探测账本，三者均受单槽和固定配置约束。所有模型调用先持久预留，UNKNOWN 不返还；内容/画像/模型版本相同的未知评估不自动再发。GitHub 限流冷却协调发现、候选复核与现有分析请求，网络超时/重试纳入有界尝试数。

重启扫描中断、不重放模型；错过调度跳过至下个未来时刻，下一轮规则可重读重叠窗口，但不重复创建候选或自动重发任何已发起评估（含 FAILED/已知 usage）。恢复备份强制关闭定时和恢复日模型评估，保留忽略/排除/水位与用量；新表全部进入备份校验。M5 先保存独立选择/复核记录，无模型也可复核；具备配置并确认风险后幂等创建原有分析任务，新增前置 hash/有效期检查与等待确认分支，不改变旧任务事实。
