| 项目 | 实际证据与结果 |
|---|---|
| 实施中的首次真实重复窗口 | 同一窗口两轮各 4 次匹配，数据库稳定 ID 唯一候选仍为 4；忽略/启用持久控制已检查。此轮早于仓库片段轮换完善，单独标 development_repeat，不冒充最终构建整轮 |
| 最终构建立即发现 | 两轮各 3 次 HTTP、读取 30 条 Issue，分别匹配 14/12；不同仓库片段合计 26 个稳定候选。均为 BOUNDED_SEARCH_INCOMPLETE，不声称穷尽来源 |
| 真实来源 | 示例 [elastic/logstash#19466](https://github.com/elastic/logstash/issues/19466)，稳定 Issue ID 5273257744、仓库 ID 1090311；仅为规则候选，不代表问题确实适合贡献 |
| 人工选择后真实复核 | 进入 WAITING_SOURCE_CONFIRMATION，保存 hash、时间、关联状态/完整性。未确认费用、未创建真实深入分析，不以“未检出”宣称不存在重复修复 |
| 正常定时 | 配置 UTC 01:00（北京时间 09:00），进程每 60 秒检查。最终构建于北京时间 09:00:18 正常触发 SCHEDULE，发出 1 次真实 HTTP 后遇限流，记录 PARTIAL/GITHUB_COOLDOWN 并释放槽。未自动重放该终态 |
| 限流之后 | 独立、主动、有界的重复窗口检查同样受搜索限流，0 个新候选。保留失败记录，未用夹具补齐。过期 reset 提示暴露的冷却边界已修复并新增测试 |

最终真实“同一窗口”重复验证及定时产生成功候选仍需在 GitHub 配额可用时补验；实施中重复证据与最终轮换发现证据分别保留。未故意耗尽配额，未修改代理/凭据绕过限流，不无限重试。

GitHub API 搜索/限流和有界 timeline 读取依据 [官方搜索文档](https://docs.github.com/en/rest/search/search)、[限流文档](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)、[Issue timeline](https://docs.github.com/en/rest/issues/timeline) 核对。搜索有延迟/结果上限/排序漂移，多请求复核非原子；适合度保留人工判断。
