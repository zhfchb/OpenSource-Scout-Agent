# 账号与独立工作台

2026-10-30，按用户明确选择扩展：每人独立工作台，各自配置模型密钥。此文覆盖此前单管理员设计中的账号、凭据和备份部分；不覆盖历史验收记录，也不引入 Redis、向量库或目标代码执行能力。

## 使用方式

1. 新用户在登录页选择“注册账号”。用户名以字母开头，3–32 位字母、数字、下划线或短横线，不区分大小写；admin、owner 等为保留名称。密码 12–256 个字符。
2. 登录后进入“设置 → 账号与个人凭据”，保存自己的 DeepSeek API Key 和可选 GitHub Token。留空保留原值，勾选清除才删除；写入后不回显，不自动测试或计费。
3. 在“模型连接”填写模型名称，凭据变量名保持默认 MODEL_API_KEY / GITHUB_TOKEN。保存后可明确同意费用，再主动测试连接。
4. 在“修改登录密码”中输入当前密码和新密码；成功后所有设备会话撤销，重新登录。

本版本采用用户名密码，不提供邮箱验证、自助找回密码、MFA 或手机号登录。单实例最多 20 个账号（含原管理员）；这是资源保护边界，不是容量验收结论。

## 原管理员接续

- 原管理员数据库、任务、计划、审核包、发现设置与用量原地保留，不转给首个注册者。
- 进入“已有本地管理员？使用原密码登录”，用原密码登录；在设置中绑定用户名。用户名不会自动替用户选择。
- 绑定后只接受用户名和账号密码登录，原免用户名入口关闭。
- `.env` 的 ADMIN_PASSWORD_HASH 仅用于首次建立原管理员账号。账号建立后改密码请使用页面，修改环境变量不会覆盖账号密码。
- 只有原管理员可在设置中查看注册账号列表及停用/启用账号。停用会撤销会话、停止该账号执行器并隐藏其公开报告，启用后恢复读取已有数据。管理员页面不提供读取其他账号私有内容或密钥的接口。

## 隔离与持久化

仍为单 Node 进程。入口 `server/index.ts` 使用账号网关；原业务应用作为只在进程内调用的工作台服务，不额外监听端口。

设 DB_PATH 为 `data/scout.sqlite`：

| 路径 | 内容 |
|---|---|
| `data/scout.sqlite` | 原管理员工作台，原有六次迁移及历史记录保留 |
| `data/scout.sqlite.accounts.sqlite` | 账号、哈希会话、加密凭据与有限安全事件 |
| `data/scout.sqlite.accounts.sqlite.key` | 自动生成的 32 字节凭据加密主密钥 |
| `data/scout.sqlite.workspaces/<随机账号ID>/scout.sqlite` | 每位新用户的独立数据库 |

账号注册表使用独立的建表版本，业务数据库仍复用 001–006 迁移。用户名不参与目录拼接。网关依据 HttpOnly 会话选择工作台，不接受浏览器提供账号 ID 来路由私有业务。公开报告仅聚合用户主动发布且仍可读取的快照，其他私有接口不会跨库查询。

每个工作台拥有自己的模型/GitHub 凭据、配置、任务、候选、计划、审核包、公开草稿与用量。新用户的凭据环境从空对象建立，不继承服务端 MODEL_API_KEY / GITHUB_TOKEN；原管理员可继续使用原服务端环境变量，并可用个人凭据覆盖。所有工作台共用一个物理执行槽，账号各自保留持久任务队列。网络故障不会自动重放付费调用。

## 密码、会话和密钥

- 密码使用独立随机盐的 scrypt 哈希；比较使用常量时间操作。密码哈希并发有上限，登录/注册等端点有限流。
- 会话随机令牌只在 HttpOnly、SameSite=Strict Cookie 中返回；服务端只存令牌摘要。生产使用 HTTPS Secure Cookie。变更接口同时校验 Origin 与 CSRF。
- 每用户最多 20 个会话；默认 12 小时，沿用服务端 SESSION_HOURS。
- 凭据用 AES-256-GCM 加密并绑定账号 ID。仅返回存在标志；密文不代替文件系统安全，数据库与主密钥都必须保密。
- 不通过日志记录请求体、Cookie 或 Authorization。更新凭据会拒绝仍有业务任务/模型测试/发现运行的账号，以免混淆在途调用归属。
- 主密钥首次创建；存在密文但主密钥丢失时拒绝启动，不用新密钥静默覆盖。主密钥长度或密文认证异常同样拒绝读取。

## 备份和部署

**原 `npm run backup` 仅备份 DB_PATH 指定的一个工作台，不能代表多账号完整备份。**

多账号全量备份必须先正常停止服务，待所有数据库关闭后，将上表四项作为同一份私有备份保存；工作台目录递归复制全部内容。恢复时也应停止服务，将四项成套恢复到相同 DB_PATH 前缀后启动。不要只恢复账号库或只恢复主密钥；不要把这些文件放进 Git、公开制品或公开下载目录。备份目录需和运行数据目录分开，避免递归复制自身。强制终止或不确定是否已关闭时，应同时保留 SQLite WAL 文件并由 SQLite 校验，不应只复制主文件。

Linux 运行账号需对 DB_PATH 所在目录拥有读写权限，使账号库、主密钥和工作台子目录可创建；创建目录权限为 0700、主密钥为 0600。Windows 应限制该数据目录的 NTFS 访问权限。密钥丢失不能由用户名密码恢复 API 凭据。向外网开放前仍需目标服务器、HTTPS 和多账号实际资源验收。

## 新增接口

| 接口 | 说明 |
|---|---|
| GET `/api/auth/options` | 注册名额与旧管理员入口是否可用 |
| POST `/api/auth/register` | 用户名、密码注册并创建会话 |
| POST `/api/auth/login` | 用户名、密码登录；未绑定原管理员可省略用户名 |
| GET `/api/admin/session` | 当前账号与 CSRF 令牌 |
| POST `/api/admin/logout` | 退出当前会话 |
| GET `/api/account` | 当前账号信息 |
| POST `/api/account/bind` | 原管理员验证原密码后绑定用户名 |
| POST `/api/account/password` | 验证原密码、修改密码并撤销全部会话 |
| GET/PUT `/api/account/credentials` | 查询存在状态或更新个人模型/GitHub 凭据 |
| GET `/api/account/users` | 管理员查看账号列表 |
| PUT `/api/account/users/:id` | 管理员停用/启用普通账号 |

原 `/api/admin/*` 业务路径保留以兼容现有页面；路径名称不表示注册用户拥有全局管理员权限，实际操作仅路由到当前账号的数据库。
