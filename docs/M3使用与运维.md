# M3：公开报告与本地运维验证

本阶段按用户确认先完成本地开发和验证；暂无可用于实测的 2核2GB Linux 服务器，不能宣称完成 M3 全部云端验收。真实模型闭环也仍需有效凭据。

当前设计新增 [M5 自动发现](M5自动发现设计.md)（未实现）：候选、画像、运行记录均为私有，不能直接进入现有公开白名单。M5 实施时须将新表/预算/游标/忽略记录加入备份校验，恢复强制关闭定时并设置模型评估恢复 guard；本页现有命令不因此已经支持新 schema。云端容量待验收项需增加发现负载，历史 43 项测试不包含 M5。

## 1. 游客与管理员入口

- 游客默认入口：`/#/reports`，只能阅读已确认发布的快照，列表每页 12 条。
- 报告链接：`/#/reports/<公开ID>`，链接中的 ID 不是内部任务 ID。
- 管理员：`/#/login`，登录后进入 `/#/workspace`。已登录时可从公开页返回管理工作台。
- 公开接口只有 GET 列表/详情；任务、设置、下载、发布、撤回、运维观察均在鉴权的管理接口内。

公开页不会默认填充假报告，只有所有者明确发布的内容可见。FIXTURE 样例与 LIVE_API 来源会分别标识；来源标识不等于结论正确、补丁运行通过或贡献获接受。

## 2. 预览、确认与撤回

完成分析后，在任务详情编辑公开标题、摘要、判断依据和疑点，点击“生成脱敏预览”。服务端另行构造白名单快照：这四类文本、repo/Issue/Commit、固定 GitHub 来源链接、LIVE_API/FIXTURE、是否有审核包、UNVERIFIED/NOT_RUN。

不复制原始 Issue 正文、源码、Diff、计划内部内容、Prompt、配置、日志、模型用量、内部任务 ID 或凭据。自由文本中的检测到的当前配置 secret、常见 token、邮箱、私有路径和自由 URL 会被处理；来源链接由服务端按已验证的 GitHub 数据生成。预览不是全面信息泄漏检测证明，所有者仍须核查全部快照，尤其是未被模式识别的敏感内容。

预览绑定来源/分析版本及内容 SHA-256，30 分钟有效，每任务只保存一个当前预览。勾选同意公开后才可发布。编辑内容、覆盖预览、来源变化或脱敏条件变化需重新预览；重复确认不会重复发布。同一任务只保留一个活动公开报告，更新先撤回再重新发布。

快照独立于后续私有任务编辑。撤回立即阻止服务端新读取，列表不再返回，详情 404，API 设置 no-store。已打开页面约每 10 秒及重新聚焦时复查；已经下载、截图或复制的内容无法收回。公开文本直接由 Vue 转义展示，Markdown/HTML 不作富文本解释；没有任意外部链接自动转换或外部脚本执行。

## 3. 存储和缓存限额

服务器环境文件配置以下上限，重启后生效；模型和任务不能修改这些硬性运营边界。

| 配置 | 默认值 | 行为 |
|---|---:|---|
| MAX_DATABASE_BYTES | 512 MiB | SQLite 主库页数上限；业务写入保留会话/撤回操作余量 |
| MAX_ARTIFACT_TOTAL_BYTES | 64 MiB | 审核包内容合计；调用模型前按单包上界预检，实际保存再检查 |
| MAX_TASKS | 1000 | 达到后拒绝新建任务，已有历史不自动删除 |
| MAX_PLANS_PER_TASK | 20 | 限制每任务计划历史版本数 |
| MAX_PUBLICATIONS | 1000 | 包括撤回记录的发布历史总数 |
| MAX_BACKUPS | 7 | 备份命令拒绝继续生成，需显式归档/处理旧数据库和清单对 |

没有源码磁盘缓存。公开快照最多 32KiB，列表请求有界，资源观察只保留最近 120 个内存样本，登录会话最多 20 个。发布预览每任务一个并有到期时间。设置页“清理过期会话与发布预览”只清理这两类过期记录，不删除任务、计划、审核包或发布历史。

SQLite WAL 自动 checkpoint 目标 1000 页、checkpoint 后 journal_size_limit 8MiB；它不是活跃 WAL 的绝对实时磁盘上限，长读者/备份期间仍可能暂增。主库大小不含 WAL、备份和日志，应监控整个数据卷并保留空间。达到配额只拒绝新工作，不静默清除已确认数据；需先备份再调整限额或另行设计归档。

## 4. 日志与 Linux 配置

生产仍是预构建静态前端和一个 Node 应用进程，无开发服务器、集群、独立 Worker 或项目代码执行。部署基础见部署运维文档。M3 增加专用 journal namespace，避免调整整机其他服务的日志策略：

```sh
sudo install -m 0644 deploy/journald@scout.conf /etc/systemd/journald@scout.conf
sudo install -m 0644 deploy/scout.service /etc/systemd/system/scout.service
sudo systemctl daemon-reload
sudo systemctl restart scout
sudo journalctl --namespace=scout -u scout -n 100
```

namespace 示例设置持久日志 100MiB、运行时日志 20MiB、单文件 10MiB、保留期 7 天，不转发到 syslog。应用仍不写请求 URL/头/正文和原始错误。示例以 Ubuntu 24.04/systemd 为目标，尚未实际部署验证；TLS 仍用 Caddy，APP_ORIGIN 必须是实际 HTTPS 源，登录 Cookie 为 Secure/HttpOnly/SameSite=Strict。

## 5. 一致性备份、校验与恢复

任务、来源、审核包、公开快照均在 SQLite 中，没有外部制品引用。新的备份命令使用 SQLite backup API 创建独立 `.sqlite`，并生成相邻 `.sqlite.manifest.json`。清单只含数据库 SHA-256、表行数和表级摘要；还校验数据库完整性、外键、计划/包/快照 hash，不导出密钥、原始会话令牌或整个表正文到清单。数据库本身仍是敏感备份，两文件都应私有保存、离机加密。

```sh
cd /opt/scout
sudo -u scout env DB_PATH=/var/lib/scout/scout.sqlite MAX_BACKUPS=7 node dist/server/backup.js /var/lib/scout/backups
node dist/server/verify-backup.js /path/to/scout-BACKUP.sqlite
# 也可 npm run backup:verify -- /path/to/scout-BACKUP.sqlite
```

备份不会迁移源库或改变活动任务状态。只读源库；分批遍历做摘要，不一次载入全部审核包。超出备份数量时明确失败，不自动删除旧副本。部分失败文件应由操作人员检查后处理。

恢复使用新的私有目标路径，绝不覆盖现有库/WAL/SHM：

```sh
sudo systemctl stop scout
node dist/server/restore.js /path/to/scout-BACKUP.sqlite /new/private/location/scout.sqlite
# 或 npm run restore -- <备份> <全新目标库>
```

恢复先核对数据库与清单。成功后保留计划、包和报告内容/hash，但清空会话与发布预览，未完成任务标 INTERRUPTED、未结用量标 UNKNOWN，**默认撤回全部公开报告**，防止旧备份复活后来撤回的内容。需要所有者重新预览、确认发布。之后确认属主/权限（目录 0700、文件 0600）、将 DB_PATH 指向恢复库，使用对应构建/迁移和私有环境配置重启。旧库完整副本保留，不与恢复库 sidecar 混用。真实云端权限、重启和恢复仍待服务器环境实测。

## 6. 容量观察与待验收

管理员设置页提供当前 RSS、进程生命周期峰值 RSS、系统总/可用内存、平台/CPU 和存储配额；每秒采样并记录 source/analysis/patch 阶段。观察数据不自动标记容量通过。

在真实 2核2GB Linux、HTTPS 和有效模型条件齐备后，可运行：

```sh
read -rs -p 'Admin password: ' scout_password
printf '%s' "$scout_password" | CAPACITY_URL=https://scout.example.com CAPACITY_SECONDS=300 npm run capacity:probe
unset scout_password
```

密码只从 stdin 读取，不放进参数、历史或结果。工具只登录、采样、退出，不触发任务或付费调用；需要同时在浏览器完成真实分析与补丁流程。JSON 默认保存在忽略目录 `data/capacity-observations.json`，标记 OBSERVATIONS_ONLY/capacityValidated=false。区分进程生命周期峰值与当前采样窗口，结合实际步骤、usage、HTTP 响应和 Linux 整机资源再判断是否适配；不能用 Windows、夹具或简单容器内存限制代替真实目标验收。

接口参考：[systemd journal namespace](https://www.freedesktop.org/software/systemd/man/latest/systemd-journald.html)、[journal 限额](https://www.freedesktop.org/software/systemd/man/253/journald.conf.html)、[Node RSS 与资源用量](https://nodejs.org/api/process.html)。
