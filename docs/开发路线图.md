# OpenSource Scout Agent 开发路线图

> 2026-10-30 用户授权扩展：[账号与独立工作台](账号与独立工作台.md) 已取代本文件中的单管理员账号、全局凭据和单库备份假设。旧阶段记录保持原样；当前为每人独立数据库、个人加密凭据及服务端共享执行槽。


版本：2.2｜2026-10-29｜v2 当前实施路线。M0–M3 有本地证据，M4-A/B 本地实现、M4-C 待真实验收、M5 本地已实现、真实验收待补；真实模型及云端验收仍待补。历史 v1.0 的旧 M0—M5 不作为执行清单；当前新增 M5 定义见本文。

## 1. 原则

所有功能经浏览器操作，应用部署在云端；2核2GB为实测目标。固定流程、单实例、单活动任务，先提供有用分析与待验证补丁。第三方代码不执行；没有运行的测试不得标通过。

每阶段交付可运行增量、实际验证、限制和下一步。没有实测不得写阶段完成；不为尚未需要的平台能力增加常驻组件。

| 阶段 | 依赖与当前结论 |
|---|---|
| M0 工程基线 | 已有本地证据，部署示例未替代真实 Linux 验收 |
| M1 Issue 分析 | 依赖 M0；本地/夹具通过，真实模型待补 |
| M2 计划与补丁 | 依赖 M1；本地/夹具通过，真实审核包待补 |
| M3 公开与运维 | 依赖 M2；本地通过，云端/容量待补 |
| M4 联调与可用性 | A/B 本地实现、54 项测试与浏览器验证通过；C 真实模型闭环未执行 |
| M5 自动发现 | 本地已实现并有规则发现/复核真实证据；正常定时成功结果、可选真实模型和容量待补 |
| v2 发布准备 | 本地检查、候选打包/校验/独立冒烟/配置预检已提供，见 [使用说明](v2发布准备.md)；真实验收缺口不变 |
| v2 发布检查 | M4 真实闭环、M5 真实 GitHub 发现与 M3 含发现负载云端补验通过 |

现状与证据入口见 [文档导航](文档导航与实施状态.md)。本文件 M0–M3 的任务保留为阶段定义，不要求从头重做，也不把缺失的真实验收取消。

## 2. M0：轻量Web工程与部署基线

- 检查实际目录、AGENTS.md、Git及Node环境，保护已有文件。
- Vue 3/TS/Vite前端，Node/TS/Fastify后端；单进程提供构建后的前端和API。
- SQLite及版本化SQL迁移、健康检查、结构化日志、配置与密钥引用。
- 管理员登录/会话/变更请求保护，任务列表和设置页面骨架。
- 运行时输入schema、限额配置、默认禁止目标代码执行。
- 锁定实际兼容版本；部署脚本/systemd、HTTPS代理示例、备份说明。

验收：前后端构建和类型检查、服务启动、健康/迁移、未登录拒绝管理操作、日志脱敏；不运行Vite或tsc常驻服务。记录可用环境的空闲内存；未取得2GB云环境时标记容量验证未执行。

## 3. M1：手动Issue分析

- 仓库/Issue链接校验，仓库有限Issue列表与选择。
- GitHub只读适配、Commit固定的有界源码文本获取。
- SQLite任务表与进程内单执行器、重复提交保护、轮询状态。
- 单模型配置、结构化分析、调用超时与调用数/Token预留。
- 中断标记和手动步骤重试、取消与attempt检查。

验收：真实公开Issue产生可核查报告，明确数据缺口；夹具验证分页限制、错误、预算、重复触发、重启中断和取消迟到结果。记录来源与实际用量；无凭据时不伪造真实调用。

## 4. M2：计划确认与待验证补丁

- 展示修改计划，确认绑定Commit和hash。
- 单次生成统一Diff和PR文案；范围/路径/格式/大小检查。
- 超范围、敏感路径或新增依赖要求修订确认；不自动修复循环。
- 私有下载、人工审核状态、手工PR链接/结果记录。

验收：至少一个真实分析可经确认生成审核包；未确认不能生成，计划变化不能复用旧确认；危险路径被拒绝。补丁统一UNVERIFIED，项目编译/测试明确NOT_RUN，人工PR状态标MANUAL。

## 5. M3：公开报告与2GB部署验证

- 白名单发布快照、预览确认、公开列表与详情、撤回。
- HTTPS、登录和下载权限、Markdown安全渲染、敏感内容测试。
- 日志/缓存/制品上限、备份与恢复实测。
- 实际2GB Linux环境运行Web、分析、补丁流程，记录峰值、响应表现和限制；按结果调整配置。

验收：访客无法执行任务或读取内部数据；公开报告无测试secret/私有路径；撤回生效；恢复后数据和制品匹配。真实运行与样例明确区分，全部F01—F12逐项给出结论。容量不达标则收敛上下文或功能，不能虚报适配。

## 6. M4：真实模型联调与可用性完善

目标：让所有者能诊断配置、主动测试连接、完成真实分析与待验证补丁，并根据失败提示恢复。详细设计见 [M4 真实模型联调设计](M4真实模型联调设计.md)。

- M4-A 配置与探测：本地诊断、设置 revision、明确费用提示、幂等连接测试、独立持久每日预算和记录；与任务共用单执行槽。
- M4-B 错误与恢复：固定错误类别/关联 ID、清晰下一步、UNKNOWN 提示；取消、迟到结果、重启不重放；备份恢复覆盖新增账本。
- M4-C 真实验收：浏览器真实 Issue → 固定来源 → 分析 → 修订/确认计划 → 单次真实补丁 → 下载核对 → 私有公开预览；实际发布由所有者选择。

交付：增量实现、迁移、M4 使用说明、夹具与浏览器验证、真实联调证据、失败和未执行项。无凭据时可完成 A/B 工程，不得将 C 标通过。没有服务器不阻塞本地 M4，M3 容量债务继续保留。

验收：F13–F15 及相关旧需求回归；一条真实模型分析和一份合法真实模型审核包，记录来源/计划/包 hash 和实际或 UNKNOWN usage；至少覆盖一个明确来源的失败分支。补丁仍 UNVERIFIED，目标编译/测试 NOT_RUN，手工 PR MANUAL。连接测试成功不替代完整闭环。全部细则见 [验收与发布标准](验收与发布标准.md)。

实施顺序：A → B → 本地综合回归 → C；按实际失败修复并重测受影响项。M4 完成不自动公开报告、不创建 PR、不部署公网、不扩大产品权限。

## 7. v2 云端发布补验

在真实 2核2GB Linux/HTTPS 环境补齐 M3：部署/登录/下载/重启、真实分析补丁峰值与整机余量、公开权限/撤回、备份校验与新路径恢复。按验收标准逐项给结论。新增 M5 承担自动发现，不接管或掩盖 M3 未完成验收；容量补验增加发现负载。

## 8. M5：轻量自动发现与候选管理（本地已实现，真实分项待补）

目标：恢复“自动发现适合我的开源贡献机会”，采用 [M5 专项设计](M5自动发现设计.md)，不恢复历史 v1.0 的完整发现/编排/执行平台。F16–F24 不与历史需求同号映射。

实际基础：已有 github/tasks/network/discovery/work-queue、SQLite 001–006 及任务/公开/发现页面；M4-A/B 与 M5 本地工程已实现。历史 M0–M5 定义、编号与证据保留。

| 子阶段 | 实施增量 | 依赖与交付 |
|---|---|---|
| M5-A | 画像/规则、立即发现、稳定 ID 去重、私有候选/忽略/收藏/仓库排除 | 依赖已有 M1 输入/只读适配；先抽取统一单槽接口，模型关闭；迁移、API、浏览器与夹具 |
| M5-B | 同进程定时/持久触发、增量水位、限流/请求预算、取消/重启、人工选择前置复核 | 依赖 A；与现有分析队列集成，验证单槽、配置冲突、未知关联及恢复 |
| M5-C | 可选模型少量评估、M4 探测协调、完整备份/恢复、真实 GitHub 验收 | 依赖 B；探测互斥依赖 M4-A/B 接口，付费评估可关闭交付并明确未验收 |

建议先协调 M4-A/B 与 M5 共用的执行槽/账本契约，再做 M5-A/B 和无模型真实 GitHub 验收；M4-C 真实付费闭环与 M3 服务器等待不阻塞发现开发。M5-C 的可选模型分支仅在有明确启用配置和验证授权后测试。

验收：手动/定时、重复触发去重、忽略持久、配置变更、限流/超时/预算/截断、重启不重复付费、与分析/探测互斥、状态未知/关联 PR、真实候选来源可核实。夹具和真实 GitHub 分开留证；不自动深入分析/补丁，不声称候选已排除所有修复。新增 evidence/M5/ 实际记录，不创建虚构通过结果。

v2 发布检查新增 M5 规则发现/候选选择/状态复核与真实 GitHub 来源要求；可选评估关闭时单独标 NOT_RUN。M3 云端补验增加发现及排队时资源/响应，不重写原 M3 记录。

## 9. 后续按需立项

搜索发现和定时扫描已纳入当前新增 M5；完整 PR 远端同步、流式进度、多模型或自动验证仍不属于当前交付。安全执行需独立威胁模型、隔离验证和资源评估；不因增加一个按钮就允许宿主运行项目代码。Postgres/Redis/向量库/分布式队列无预定引入日期。

建议证据目录：evidence/M0/、M1/、M2/、M3/、M4/、M5/。历史记录不覆盖，M3 云端补验单独追加。每份记录日期、环境、版本、命令、真实结果与未执行项，不包含真实凭据。
