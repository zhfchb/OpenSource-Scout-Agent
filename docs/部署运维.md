# M0 单实例 Linux 部署与运维

当前已扩展到 M3 本地实现；新增公开报告、独立日志 namespace、配额、备份清单及恢复保护见 [M3 使用与运维](M3使用与运维.md)。本页保留初始部署基线，真实 Linux/HTTPS/2GB 验收仍未执行。

目标：Ubuntu 24.04、Node 24 LTS 最新安全补丁、systemd、Caddy、持久本地磁盘。配置示例尚未在 Linux 云服务器执行。只运行一个应用实例，禁止 PM2 cluster、多副本、共享网络盘 SQLite。不要在服务运行中手动运行迁移或第二个应用实例。

## 1. 构建与安装

在开发机或 CI 运行 `npm ci && npm run typecheck && npm run build && npm test`。发布包包含 `dist/`、`frontend/dist/`、`migrations/`、`scripts/`、package.json、package-lock.json；不包含 .env、数据、日志和 node_modules。

在目标机创建系统用户 scout；把发布包放到 root 管理的 `/opt/scout`。由于 better-sqlite3 是原生扩展，不能复制 Windows 的 node_modules；目标机运行 `npm ci --omit=dev` 安装锁定的正式依赖（不编译前后端业务代码）。若对应平台无预编译扩展，需要在同架构 Linux CI 制作包含原生依赖的发布包；不可临时在 2GB 服务上引入一套常驻构建进程。

创建 `/etc/scout`（root:scout，0750），将 `.env.example` 复制为 `/etc/scout/scout.env`（root:scout，0640）；填写真实域名、密码 hash、DB_PATH=/var/lib/scout/scout.sqlite。密钥留在此文件，设置页只填写其变量名称。生成 hash 的命令见 README，切勿把真实密码写进 Shell 参数。

复制 deploy/scout.service 到 `/etc/systemd/system/scout.service`；确认 Node 路径为 `/usr/bin/node`。systemd 的 StateDirectory 自动创建私有数据目录。

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now scout
sudo systemctl status scout
curl --fail http://127.0.0.1:3000/api/health
```

启动会自动校验并应用 migrations/ 下有序 SQL；校验和不一致则拒绝启动。升级前停服务并备份，不修改已应用的 SQL；新增递增迁移。当前 M0 只建立 settings、sessions、tasks 表，其余业务表随下一阶段增量加入。

## 2. HTTPS

安装 Caddy，替换 deploy/Caddyfile 中域名并指向配置文件。域名 A/AAAA 应正确指向服务器，放行 80/443，应用 3000 只监听回环地址。APP_ORIGIN 必须与浏览器使用的 HTTPS 源完全一致（无尾斜杠）。

```sh
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

应用不信任转发 IP，反向代理下登录限速默认共享回环 IP 的每分钟 5 次额度，符合单管理员场景。不要通过开启任意 trustProxy 绕过该边界。生产 Cookie 强制 Secure、HttpOnly、SameSite=Strict；写请求校验 Origin 与 CSRF。前端不保存原始密码或会话到 localStorage。健康端点仅返回应用/数据库状态。

## 3. 日志与限额

不记录请求 URL、查询、头、Body 或原始错误对象；只记录方法、状态和关联 ID，特定敏感字段另作脱敏。严禁新增完整请求/模型/源码日志。日志交给 journal，生产需配置 `/etc/systemd/journald.conf.d/scout-limits.conf`，例如 `SystemMaxUse=100M`、`MaxRetentionSec=7day`；此为整机 journal 设置，运维人员须评估其他服务后应用。

systemd 将应用内存限制为 768MB、V8 堆为 384MB；这些是初始保护阈值，不是 2GB 容量实测。设置数值均受运行时 schema 限制，单活动任务与禁止目标执行是服务端不可修改策略。M1 调用前才会落实设置中的业务预算；当前无外部调用。

## 4. 一致性备份和恢复

M0 没有制品文件；在线 SQLite 备份使用驱动 backup API，不能只复制活跃的 .sqlite 文件忽略 WAL。备份命令不会迁移或修改任务状态：

```sh
cd /opt/scout
sudo -u scout DB_PATH=/var/lib/scout/scout.sqlite node dist/server/backup.js /var/lib/scout/backups
```

每日按需备份、离机加密保存、保留最近 7 份并监控磁盘；备份含私有设置及会话，视为敏感文件。自动定时与自动清理当前未配置，须由运维显式配置。`npm run backup -- <目录>` 支持读取当前工作目录 .env；systemd 的 EnvironmentFile 不会自动传给交互 Shell，线上按上述命令显式指定 DB_PATH。

恢复：按 M3 文档使用 `npm run backup:verify -- <备份>` 与 `npm run restore -- <备份> <全新目标库>`，停止服务后再切换 DB_PATH。不要仅复制活跃主库或直接覆盖旧库。恢复会清空会话和发布预览，并默认撤回公开报告，防止旧备份恢复已撤回内容；需重新预览发布。计划、审核包和报告内容及 hash 保留。本地恢复演练已完成，真实云端恢复仍待验收。
