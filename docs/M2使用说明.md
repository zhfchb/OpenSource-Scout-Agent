# M2：计划确认与待验证补丁审核包

此流程继续作为 v2 补丁边界；新增 [M5 自动发现](M5自动发现设计.md) 已本地实现，候选选择不代替这里的 Commit/计划 hash 确认，也不自动生成补丁。文中“M2 没有配额”等限制属于该阶段；当前 M3 已加入配额，见 [M3 使用与运维](M3使用与运维.md)。不改写 M2 当时验收事实。

## 使用流程

1. 按 M1 使用说明配置服务器密钥引用和可用 DeepSeek 模型，从网页完成一次真实分析。无有效凭据时不运行真实分析或生成；测试夹具不作为真实成果。
2. 在任务详情的“确认修改计划”填写具体步骤及精确允许路径（每行一个），参考实际提供给模型的源码列表。当前仅允许修改已经保存在该任务快照里的文件。
3. 对配置、鉴权、迁移、脚本等敏感文件，或依赖声明/新外部导入，按实际计划明确勾选授权。危险路径始终拒绝，勾选不能放开 `.git`、`.env`、路径跳转或不受支持的文件。
4. 点击保存计划。服务端创建新版本及 SHA-256，绑定任务、Commit、源快照、分析内容、步骤、路径和两个授权标志。核对后点击“确认当前 Commit 和计划”。修改编辑框但尚未保存时，确认和生成均禁用。
5. 点击“生成一版待验证补丁”。请求先持久标记该版已使用，并进入原有单执行器；重复提交返回同一任务，不会新增调用。每版最多发起一次，没有自动修复循环。
6. 查看统一 Diff、PR 草稿及非执行性检查。私有下载包括完整审核包 JSON、原始 `.patch` 和 PR 草稿 `.md`。下载文件名含 UNVERIFIED；JSON 字节与页面 SHA-256 可核对。
7. 人工审阅后记录“已人工审核”或“拒绝”。已审核也不会改成验证通过；拒绝后停止下载。若修订计划，旧确认和旧审核包下载失效，历史数据仍留库。
8. 在系统外验证和手工提交 PR 后，可填写当前目标仓库的 GitHub `/pull/编号` 链接和状态。它仅是 MANUAL 记录，不代表网站已提交、同步或向 GitHub 核验。

## 补丁支持范围

当前保守支持普通 ASCII 相对路径上的既有 UTF-8/LF 文本文件，统一 Diff 使用相同的 `a/path`、`b/path`。不支持新增/删除/重命名文件、二进制、符号链接、模式变更、带空格或非 ASCII 路径、传统无 Git 文件头的 Diff、多父合并 Diff、CRLF 源文件修改。不支持的格式明确失败，不悄悄转换或应用。

逐文件检查精确范围、重复文件、路径、Hunk 数量和行号、旧行是否等于固定快照、文件大小上限。依赖检查包括依赖声明文件与新增字面量外部导入/计算导入的保守文本扫描，不是语言语义证明，可能误报或漏掉间接依赖；仍需人工检查。

静态检查不调用 `git apply`、不把生成内容写入目标目录、不安装依赖、不编译/测试、不执行 hooks/CI。检查 PASS 只说明该项静态检查通过，**不证明补丁可以应用、运行或解决 Issue**。所有审核包固定 `patchStatus=UNVERIFIED`，application/compilation/tests 为 NOT_RUN。PR 草稿也会附相同说明。

超范围、敏感路径或新依赖未授权时，不保存可下载的补丁，显示固定错误代码。需要核对并保存新计划版本、重新确认。扩展到快照外文件须先重新进行包含相应源码的分析；M2 没有偷偷补取新源码或扩大旧计划范围的入口。

## 预算、取消和重启

分析和补丁共用同一任务的累计调用/Token 预算。补丁调用前按完整确认输入的 UTF-8 字节保守估计，并预留最多 4096 输出 Token；不会为了塞入预算而静默裁剪已确认路径。超过上下文时缩小计划范围；超过任务累计预算则不再调用。

取消先更新状态及 attempt，再中止请求，迟到结果不得保存成审核包；用量仍尽量记入原调用。重启遗留 QUEUED/RUNNING 标为 INTERRUPTED，预留用量为 UNKNOWN。已请求的计划不再重放，须手动保存新版本并重新确认，明确承担可能重复计费的风险。分析阶段的普通步骤重试仍按 M1 方式工作。

## 持久化与运维

迁移 `003_patch_review.sql` 新增 plans、artifacts、manual_pr_records，并区分 ANALYSIS/PATCH 阶段，持久记录 LIVE_API/FIXTURE 来源。旧数据继续保留；旧 M1 来源默认为 LIVE_API，测试数据库不应迁入生产。

审核包用受限 JSON 文本存 SQLite，保存不可变内容、字节数及 SHA-256，与步骤/任务完成状态同事务提交；审核状态单独保存，不改写原始审核包。下载再次核对当前计划、来源/分析 hash、包 hash、字节数、人工拒绝状态及登录权限。旧计划和原始包仍保留用于内部审计，但不提供旧版下载。

M2 没有外部制品文件，一致性 SQLite backup API 覆盖计划、包、审核状态和手工 PR。Windows 本地备份恢复已核对库完整性与恢复后的可下载包 hash；真实 Linux 部署和 2GB 容量仍待 M3 实测。当前没有自动制品保留策略/数据库容量清理，部署前要监控磁盘；不得据此声称任意任务规模可长期运行。
