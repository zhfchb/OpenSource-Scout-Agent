# M5：自动发现与候选管理

版本：2.2｜实施更新：2026-10-30。画像、发现、候选、调度、复核和可选评估已本地实现；78 项测试与浏览器回归通过。真实立即发现与复核已有记录，正常定时触发遇到 GitHub 限流，成功结果仍待补验。真实模型与云端容量未验收，见 [实际记录](../evidence/M5/验收记录.md)。

## 1. 配置与首次发现

所有者在浏览器登录，进入“机会发现”，点击“编辑技术画像”。默认语言 Java/Python，偏好 good first issue/help wanted；调整活跃度、规模代理条件和仓库排除。标签偏好不保证贡献资格，star 不代表代码复杂度。画像编辑带版本冲突保护，保存本身不扫描、不调用模型。

保存后点击“立即发现”。规则发现只需可用 GitHub 只读 API，不要求模型；匿名请求可能更易限流。页面显示排队、轮次预算、扫描数量、过滤原因与未完成范围。不因没有结果自动扩大查询或反复调用模型。

## 2. 定时与可选评估

定时初始关闭。明确启用后默认每天 UTC 02:00（北京时间 10:00），可调整每日整点或关闭。云端进程检查到期，浏览器关闭不影响已启用调度。停机错过的轮次跳过，不恢复后连跑；重启未完成轮次标中断，可手动发起新轮次。

模型评估默认关闭。开启前显示可能持续计费，并受每轮/每日调用和 Token 上限约束；只评价少量 Issue 摘要，不整仓分析。未配置/预算不足显示 NOT_RUN，不确定用量为 UNKNOWN，不包装成模型推荐。取消一轮不关闭下次定时，关闭定时不等于忽略候选。

## 3. 阅读和管理候选

列表展示仓库、Issue、来源、匹配理由、疑点、最后检查时间和规则/模型来源。候选仅表示可能值得贡献，可能已过期、有人认领或已有未发现修复。不完整扫描会标部分完成。

收藏保留关注；忽略后不再推荐，重扫不解除。恢复须到“已忽略”明确点“重新启用”。排除仓库过滤新推荐；解除排除不自动恢复已忽略项，仍需重新匹配/复核。已创建分析不会随忽略/排除自动取消，须到任务页单独取消。

## 4. 人工选择和复核

点候选后点击“选择并复核来源”，只创建人工选择请求，经单槽先读当前 Issue/仓库及有限关联修复/PR。关闭或仓库不可贡献时停止付费分析；开放关联 PR 或信息未知时展示来源/风险并等待确认。一个交叉引用的已合并 PR 不能证明仍开放的 Issue 已修复。未检出关联不代表排除所有重复修复，确认五分钟过期或内容改变须重新检查。只有勾选风险及费用确认后，“开始深入分析”才进入现有任务；领取槽及付费前再次核对。

之后使用 [M1 分析流程](M1使用说明.md)、[M2 计划确认与审核下载](M2使用说明.md)。规则发现无需模型，深入分析需要有效模型配置/预算；不完整时提示补齐，不自动开始。选择不能代替计划确认；补丁 UNVERIFIED，目标编译/测试 NOT_RUN，验证与提交在系统外完成。

## 5. 失败、恢复与限制

限流显示冷却/未知原因并释放槽，不无限重试；预算/分页耗尽显示缺口。新画像用于后续轮次，当前禁用付费/排除/忽略即时收紧。中断可能已付费，UNKNOWN 评估不自动重发；明确重新评估仍受限额。

恢复备份后定时和可选评估关闭，恢复当日发现模型评估禁用；核对旧水位/偏好后重新启用。候选/画像均私有，不自动进入游客报告。细则见 [M5 设计](M5自动发现设计.md)，验收见 [验收标准](验收与发布标准.md)。真实付费评估未执行。

## 6. 具体按钮与数据边界

- 默认推荐排除已忽略、已排除仓库和已有分析选择关联的候选。“全部候选”仍可打开原记录、关联任务和来源。选择失败可打开原任务手动重试；确认可能重复工作/新费用后，可新建选择并重新复核。扫描不会自动重建分析。
- 仓库可从候选直接排除，也可在画像中填公开 GitHub 仓库链接“解析并排除公开仓库”。只读一份元信息获取稳定 ID；执行槽或队列占用时立即拒绝，不并行访问。解除排除后仍需重新匹配/复核，不恢复忽略项。
- 轮次结果 COMPLETED 只表示本轮已读取范围；分页、条数、字节、网络、时间或评估限制会记录 PARTIAL/具体原因。不保证扫描全部仓库，不将未返回解释为不适合。仓库片段/语言轮换，不能无限追平历史。
- 网络并发 1、统一 FIFO 等待队列最多 10。发现、复核、分析、补丁与 M4 探测共用槽；M4 探测始终不排队。候选每页 20，总量 5000；来源摘要 20000、发现轮次 1000，达到后拒绝新增，不删除忽略记录/收藏/用量。
- 旧任务没有伪造候选关联。队列表用 TASK + 任务 phase 表示 ANALYSIS/PATCH。M5 待来源确认任务沿用既有 WAITING_CONFIRMATION，并显式标记 source_gate_status=WAITING_SOURCE_CONFIRMATION；选择/复核表保存专用状态，避免重建旧任务状态约束。
- 公开/归档、稳定 ID、Issue 状态/更新/标题/全文 hash、assignee、有限 PR 状态及完整性参与风险 hash。读取时间不参与 hash；GitHub 多请求非原子，确认后仍存在外部变化竞态。

管理员 API 位于 `/api/admin/discovery/`：profile GET/PUT、runs POST/GET/取消、candidates 分页/详情/actions/select/reevaluate、selections 详情/refresh/confirm、exclusions/resolve。保存画像请求 `{profile, expectedRevision, acknowledgeCost}`；立即发现 `{requestKey, revision}`；确认 `{hash, acknowledgeCost:true}`。GET 不发起外部调用。所有变更鉴权、Origin/CSRF 且严格校验。

## 7. 限额与运维

画像可在 [设计资源表](M5自动发现设计.md#7-资源网络与模型预算) 硬上限内调低/调高；硬上限还可通过服务端环境变量收紧，例如 `DISCOVERY_HARD_MAX_REPOS=20`、`DISCOVERY_HARD_DAILY_HTTP=500`、`DISCOVERY_HARD_TIMEOUT_MS=30000`。变量名按字段大写下划线生成，重启生效；无效值拒绝启动。新画像默认按收紧的上限裁剪默认值，已有画像运行前仍需符合硬边界。

HTTP 尝试在发送前记账，短重试也计入；每个网络/5xx 请求最多一次短重试，无限流重试或长时间等待。按 core/search 保存冷却；core 主配额耗尽同时阻止其他 GitHub 读取。缺失/过期 retry/reset 提示使用 15 分钟冷却。展示的字节数是应用读取的有界 JSON 载荷，非网络线速流量。

评估只发送画像必要字段和最多 4KiB Issue 文本，不读取源码，输出最多 512 Token；预留固定序列化请求字节上界+128+512。每轮/每日账本独立于 M4 探测，未知用量保留原日预留。相同候选内容/画像评估 fingerprint/模型设置版本已 dispatch 的记录不跨轮重放，失败且已知 usage 也不例外；主动重新评估新增 attempt，仍受预算控制。

新增迁移 006，不改 001–005。新版 backup/restore 包含全部 M5 表；源备份先验证，目标副本迁移、未完成项中断、关闭调度/评估、持久 guard 至下个 UTC 日。规则发现仍可手动运行。运维页显示候选/轮次/队列数量，运行观察包含 discovery/recheck/evaluation 阶段，不能据此声称通过 2核2GB 容量验收。
