# OpenSource Scout Agent 决策与变更记录

版本：2.2｜2026-10-29｜状态：M0–M3 有本地实施记录；M4-A/B 本地已实施、M4-C 待真实验收，M5 设计待实现，真实模型、自动发现与云端验收待补。

## 1. 历史与当前优先级

原31项决策、原始来源及v1.0五份设计完整保存在 [历史归档/v1.0/设计决策记录.md](历史归档/v1.0/设计决策记录.md) 及同目录配套文件中，未删改。它们用于解释历史，不再作为当前开发要求。当前PRD、ARCHITECTURE、ROADMAP、CODEX_START采用本次新决策；冲突时当前版本优先。

来源是本次用户讨论：全部功能云端运行、用户只用浏览器；个人网站以2GB内存为目标；削减复杂功能；技术选择第一个方案Vue + TypeScript + Node.js/Fastify + SQLite；用户要求同步文档。单进程、具体库、页面和分期是落实上述方向的工程默认，不冒充用户逐项指定。

## 2. ADR-032：精简功能与网页操作

演进说明：本节保留当时削减决定；其中“不自动发现/不定时扫描”已由 ADR-037 部分替代，不作为当前禁止 M5 的要求。其余权限/执行边界继续有效。

日期：2026-10-29。

问题：旧方案为持续自治与平台扩展引入大量状态、调度、评测和隔离执行工作，超出当前个人工具和资源目标。

决定：只做Web入口、手动输入、固定分析步骤、计划确认、一版补丁、人工审核下载、可选发布；不自动发现、不定时扫描、不自动修复、不执行目标项目、不自动提交和同步PR。不要求用户电脑运行后台。

影响：替代D02—D04中动态发现和分层框架的当前实现安排；简化D06、D11—D16、D20—D21、D24—D30；D08管理页面提前第一版。原有独立评分、证据等级和复杂门禁不再硬性要求，用来源、不确定性、非执行性检查和待验证标识代替。

保留：D01人工审核、D18个人/公开只读、D19真实记录、D22只读GitHub、D31核心闭环优先。D17/D29执行隔离不是被取消，而是因当前不执行第三方代码不建设执行面；未来执行前重新立项并验证。

代价：不能自动证明补丁可运行；人工承担系统外验证和提交，长任务中断需点击重试。第一版成果称“待验证补丁审核包”，不称完整自动贡献闭环。

## 3. ADR-033：全栈TypeScript与单进程部署

日期：2026-10-29。

决定：Vue 3/TypeScript/Vite，Node.js受支持LTS/TypeScript/Fastify，SQLite/本地制品；一个后端进程提供静态页面、API和单任务执行器。模型通过在线API。前后端本机或CI构建，云端只运行正式产物。

替代：D07 LangGraph与专职Agent、D10多职责独立部署、D11 APScheduler/队列/Worker、D12语义检索、D13多模型路由的原实施要求，以及原Python/FastAPI、SQLAlchemy/Alembic默认方案。

不引入：Python应用运行时、Redis、Postgres、向量库、Node集群、常驻前端开发服务器、LangGraph、Runner与Docker socket。库版本和SQLite驱动在M0验证锁定；HTTPS使用轻量反向代理。Docker Compose不再是必需前提。

代价：没有自动Checkpoint恢复；同步SQLite需严格限制查询；CPU密集任务不适合Web事件循环。以后有明确需求再扩展，不预先建设平台。

## 4. ADR-034：2GB容量与真实性

2核2GB、40—60GB SSD Linux作为目标环境，不承诺未测试性能；无本地模型、无第三方构建测试，单活动任务、有界源码和制品。内存预算和供应商限额由实测决定，不能靠假设RSS得出可部署结论。

补丁一律UNVERIFIED；检查明确类型与结果，项目测试NOT_RUN；人工PR状态来源MANUAL。密钥、权限、发布预览、重复提交防护、任务持久化、限额和安全渲染仍是第一版必要能力。

## 5. 后续治理

低风险可逆实现选择记录默认后推进；改变用户工作方式、执行第三方代码、GitHub写权限、公开范围或部署资源假设时重新说明影响并按当次授权处理。新增ADR保留替代关系，不覆盖历史。当前已有 M0–M3 本地实现与测试记录，尚无完整真实模型及云端部署验收证据。

## 6. ADR-035：M4 联调与可用性收口

日期：2026-10-29。来源：用户要求按 v2 路线和历史文档完善全套 v2 文档；M4 名称和下列细节为本次工程设计，不冒充逐项历史决策。

问题：路线只到 M3，真实模型闭环和服务器验收缺失，配置错误难以在实际调用前定位。

决定：新增 M4“真实模型联调与可用性完善”，覆盖本地配置诊断、主动付费连接测试、错误恢复和真实闭环验收。仍是单 DeepSeek 配置模型；不恢复历史旧 M4 的沙箱测试、独立 Agent 审查或自动修复。M3 的云端/2GB 验收单独保留，M4 本地工作不等于上线。

代价：增加 settings revision、探测持久账本、执行槽互斥和迁移/备份回归。每 UTC 日 5 次/10000 Token 与 60 秒间隔为初始工程限额，可按实测调整，不是供应商规则。连接成功仅证明最小请求成功；真实分析与补丁仍需另验收。

## 7. ADR-036：文档与运行事实分离

设计修订号 2.1 仍属于产品 v2，不作为已发布软件版本。已有验收记录保持原事实；新增需求 F13–F15、接口和表明确待实现。配置与付费操作不因阅读启动模板而执行；报告发布须原有预览确认。正式发布需同时满足真实模型证据与云端目标验收。

历史保留 D01/D18/D19/D22/D31 的人工控制、真实展示和最小权限意图；D07/D09/D11/D16/D20 等超出精简范围的实现不因历史存在重新生效。完整取舍见文档导航，不再预定平台化扩容日程。

## 8. ADR-037：恢复轻量自动发现这一核心能力

日期：2026-10-29。来源：用户明确要求恢复技术画像、立即/定时 GitHub 发现、低成本筛选、私有推荐、人工选择、去重增量、候选管理和分析前状态复核；本次仅修订文档。

问题：手动输入 Issue 后生成补丁削弱“帮用户找到适合的贡献机会”的价值。2核2GB 是待实测目标，不能据此将发现永久移出核心流程，也不能直接恢复高资源平台架构。

决定：新增当前 v2 的 M5，恢复历史 D03/D24/D25 的画像、公开仓库/Issue 发现和增量周期扫描意图，D04 的先廉价过滤再少量评估思路，以及 D15 的人工决策。以结构化条件/确定性规则为主、在线单模型评估可选，发现阶段不读取整仓或源码。候选不自动转为分析或补丁，分析前有限复核状态和关联修复/PR，无法判断明确 UNKNOWN。

替代关系：部分替代 ADR-032 的手动输入唯一入口/不自动发现/不定时扫描，以及上一轮路线中的搜索发现延期决定；不改变 M0–M4 阶段定义和历史证据。ADR-033 单进程约束保留，增加的是同进程定时唤醒，不是独立 Scheduler 服务。历史旧 M5/V1 依然不生效。

工程默认：一个活动画像，Java/Python、偏好新手/求助标签、活跃度及 star 代理条件；定时初始关闭，明确启用后默认每日 UTC 02:00；规则不依赖模型，评估默认关闭。具体数值/时间/资源表是可调整工程默认，不冒充用户逐项指定。详见 [M5 设计](M5自动发现设计.md)。

代价：新增画像版本、稳定 ID、候选偏好 tombstone、运行/水位/预算、轻量调度、前置复核和队列协调；需扩展现有网络适配获取有界限流元信息，备份恢复与容量也需补验。搜索不完整/延迟、标签不规范、关联修复遗漏、长队列与模型误判仍存在，必须显示限制，不保证候选一定适合提交。

保留：Vue/TS/Node/Fastify/SQLite，云端浏览器操作，单实例/单 Node/单活动槽；无 Redis/Postgres/向量库/LangGraph/多 Agent/独立 Worker，无 clone/fork/push/PR 写、目标构建测试或自动修复。UNVERIFIED/NOT_RUN/MANUAL 和系统外验证提交不变。

验收与治理：新增 F16–F24，分开记录夹具、真实 GitHub 和可选真实模型。未执行不得通过；现有 43 项测试不构成发现证据。M5 实现后须按发现负载重新补验 2核2GB，不推翻或伪造此前本地结果。
