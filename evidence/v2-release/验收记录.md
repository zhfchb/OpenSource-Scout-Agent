## 本次操作入口

```sh
npm run release:check -- --require-ready
npm run release:pack
npm run release:verify -- data/releases/<candidate.tar.gz>
npm run release:extract -- data/releases/<candidate.tar.gz> <new-directory>
npm run release:smoke -- data/releases/<candidate.tar.gz>
npm run deploy:check -- .env.example
```

`--require-ready` 完成本地检查后按预期返回 2；不把缺少真实验收写成就绪成功。示例配置预检按预期返回 1。其他命令的本地候选、SHA、文件清单与 Commit 见忽略目录 `data/releases/latest.json`、同名 `.sha256`、包内 RELEASE-MANIFEST.json，以及 check/smoke JSON。最终候选绑定最终干净提交，摘要不反写入源码，避免 Commit/包 hash 循环依赖。

## 首轮 CI 发现并修复的跨平台差异

首轮 GitHub Ubuntu 24.04 CI 在文档摘要检查处拒绝：Windows 工作区清单按 CRLF 字节计算，而 Git 提交依 .gitattributes 存 LF。修复为清单及声明 Markdown 与 Git LF 字节一致，历史归档正文及 Git blob 未改写；增加 docs:manifest 显式刷新工具、CRLF 拒绝/规范化回归与固定错误码输出。修复后的实际 CI 结果以对应 GitHub 运行记录为准。
