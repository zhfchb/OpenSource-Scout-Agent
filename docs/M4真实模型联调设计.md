# M4：真实模型联调与可用性完善

版本：2.2｜2026-10-29｜待实现设计；本文中的新接口、表、错误码和页面行为均不是当前可用能力。

关联需求：现有 F04–F09、F11、F12；新增 F13 配置诊断、F14 连接测试、F15 可操作错误提示。前提是 M0–M3 本地工程基线可用；无服务器不阻塞本地开发，无有效模型凭据则真实验收保持未执行。

v2 文档 2.2 新增 [M5 自动发现](M5自动发现设计.md)，不覆盖本 M4 阶段定义。M5 实现时发现/前置复核也纳入本页“业务任务/执行槽”：任一活动或排队工作均阻止探测启动；探测占槽时发现仅可按统一队列入队。模型探测账本与发现评估账本各自受限，不能互相借额度；复用同一持久恢复 guard 扩展发现评估禁用期，历史 M4 目标不因此视为已实现。

## 1. 目标与范围

让所有者判断模型配置是否可用，完成一次真实 Issue 分析、计划确认、补丁审核包与自愿发布，并能根据错误恢复。保持单 Node、SQLite、单活动外部调用执行槽、固定 DeepSeek 端点和单个配置模型。不给任务、网页或模型输入新增任意 API 地址，不增加模型路由、代理管理、自动修复或第三方项目执行。

本阶段采用现有模型适配和 JSON 输出能力。供应商支持的具体模型、参数与用量行为在实施联调时查官方资料并记录日期；这里不预设型号、价格或吞吐保证。

## 2. 设置页交互

设置页按“当前保存配置 → 本地检查 → 可选真实连接测试”呈现。保存不自动请求供应商。密钥仍由服务端环境文件注入；页面只提交环境变量名称，诊断仅返回“已配置/未配置”，不返回长度、前后缀、指纹、环境变量值或完整环境清单。

本地检查验证字段、模型是否填写、引用变量是否存在、限额组合是否足以容纳最小测试请求；不联网、不消费模型额度。GitHub 凭据缺失为提示：公开仓库可匿名读取但容易限流，不将其等同于模型配置失败。

连接测试按钮写明“将发起一次真实模型请求，可能计费”；只有所有者主动点击才发起。结果显示时间、配置版本、状态、耗时、实际 Token 或未知；说明“连接/最小 JSON 校验通过”只代表此次探测成功，不证明源码分析准确或补丁可用。编辑未保存、服务重启或配置改变后，旧成功结果显示历史状态，不继续标当前配置可用。

测试过程中禁用重复提交；页面刷新从持久记录恢复；轮询只读取状态。真实分析和连接测试争用同一执行槽：有活动或排队业务任务时拒绝开始探测，不自动排队、不等待后突然计费；探测期间新任务可按原规则入队，待探测结束再领取。客户端断开不触发新调用。

服务每次启动生成非秘密 bootId，诊断返回当前 bootId，探测记录保存发起时 bootId；只有 SUCCEEDED 且 revision、bootId 均匹配当前服务时显示“本次服务配置下最近测试成功”。它仍非持续可用保证。重启后历史记录保留但 current=false，不需对密钥求 hash 或在设置未变时伪造 revision。

## 3. 拟新增接口与契约

接口沿用管理员鉴权、Origin/CSRF、no-store、固定错误返回与运行时 schema；GET 无副作用。以下路径为拟定设计，实施时与现有路由统一。

| 接口 | 请求 | 结果/约束 |
|---|---|---|
| GET `/api/admin/model-diagnostics` | 无 | 当前保存设置的版本、模型、引用存在状态、检查项与下一步；不联网 |
| POST `/api/admin/model-tests` | `requestKey`、`settingsRevision`、`acknowledgeCost=true` | 持久预留后返回 202 与测试 ID；重复 key 返回原记录，不再调用 |
| GET `/api/admin/model-tests/:id` | 测试 ID | 私有脱敏结果；无原始请求、响应、Prompt 或凭据 |
| POST `/api/admin/model-tests/:id/cancel` | 当前 attempt | 尝试中止；已结束时返回当前结果；迟到结果不改取消状态 |

设置版本采用单调 revision，保存时带预期版本，冲突返回 409；旧任务继续使用其已有不可变设置快照。服务器在事务中比较 revision、执行槽及预算，再创建测试。相同 key 携带不同内容返回 409；只保存当前一个未结束探测。测试请求体不接受密钥、端点或自由 Prompt。

## 4. 测试请求、限额与计费

只发送服务端固定的短 JSON 探测提示，不发送 Issue、源码、数据库内容或生产配置。复用有界网络读取、超时、禁止重定向、凭据回显检查；最大输出 64 Token，响应上限 16KiB，超时为设置值且不超过 30 秒。成功要求 HTTP 成功、完整响应、未截断且得到约定 JSON；网络成功但格式不符单独报错。

调用前按固定请求 UTF-8 字节上界加 128 的保守余量及 64 输出 Token 预留，不把字节估计当真实 Token。模型测试有独立持久账本，不消耗某个业务任务预算，也不能绕过运营上限：每 UTC 日最多 5 次、累计最多 10000 个“已知实际或未知预留”Token；另设每 60 秒最多发起一次。页面显示 UTC 日重置对应的北京时间。上限是 M4 初始工程默认，非供应商额度；修改需服务端配置、重启及文档同步。

实际 usage 可用即结算，即使后续 JSON 检查失败。缺失、超时、取消或网络结果不确定时保留预留并记 UNKNOWN；不自动返还、不自动重试。跨日启动的调用归属预留时的 UTC 日；重启、配置变更不能重置累计账本。达到限额明确拒绝，不提供网页一键清零。无价格和账单核验时不显示精确金额。

## 5. 数据、状态和恢复

拟新增递增迁移（在当前 004 之后编号，实施前复核），不得修改 001–004。settings 增加 revision；新增 `model_tests`：ID、requestKey 唯一、settingsRevision、模型/引用名称快照、attempt、状态、固定错误码、预留日/Token、已知 usage 或 UNKNOWN、开始/结束时间和耗时。不存 secret、原始响应或自由内容。不得将 secret 指纹作为配置版本。

状态：`RUNNING → SUCCEEDED | FAILED | CANCELLED`；重启遗留 RUNNING → INTERRUPTED，未结算用量 UNKNOWN，不重放。取消先持久更新 attempt 和状态再中止请求；迟到 usage 只允许结算原调用账本，不能恢复成功状态。设置变更不取消已发起请求，其结果只归旧 revision。

事务内完成额度与执行槽检查/领取，网络在事务外；结束后释放槽并继续原任务执行器。恢复、备份清单、存储观察必须纳入新表；旧备份升级后以空账本开始，恢复可能无法反映备份之后的调用，应提示供应商费用以账单为准，恢复当日禁用新探测至下个 UTC 日，避免回退账本立即重用额度。

测试记录纳入数据库配额；最多保留 1000 条，达到后拒绝新测试，不自动删除审计记录。日预算使用账本聚合且有索引，不因列表分页或 UI 隐藏改变。

恢复限制写入同库新增单行 `model_test_guard`（`blockedUntilUtc`），不放在进程内存。升级后的恢复工具在目标副本完成迁移后、交付可启动目标库之前写入下个 UTC 日零点；备份不含此表的旧库同样处理。启动读取该值，重启不清除；普通新建空库初始化为无禁用期。旧版恢复工具不作为 M4 支持入口，必须先使用新版工具重新恢复。备份清单包含 guard；恢复时重设禁用期是明确的恢复后变换，不冒充与备份内容完全相同。增加旧备份恢复、跨日和恢复后重复重启测试。

## 6. 错误与恢复设计

下面是 M4 面向用户的错误分类；现有领域错误码保留，通过统一展示映射关联，不为改文案丢掉原机器码。

| 分类 | 用户提示与动作 | 自动模型重试 |
|---|---|---|
| 未配置/引用缺失 | 配置模型或在服务端设置引用变量并重启 | 无 |
| 设置已变更/任务占用 | 刷新当前配置；等待业务任务结束后主动测试 | 无 |
| 凭据或权限错误 | 核对供应商账号、密钥权限与模型授权 | 无 |
| 限流或供应商额度不足 | 显示可确认的分类；无法区分时提示检查额度/限流 | 无 |
| 本地预算不足 | 显示剩余额度或重置时间；不建议反复创建任务绕限额 | 无 |
| 网络/超时/远端不可用 | 检查服务端联网，提示可能已计费，再由用户决定重试 | 无 |
| JSON 不合规/截断/引文不符 | 展示具体检查类别；调整计划或配置，重新确认后再调用 | 无 |
| Diff 不支持/范围不符 | 给出受支持格式和允许路径；修订计划并重新确认 | 无 |

不展示供应商原始响应体、原始异常或堆栈。页面提供固定错误码、请求关联 ID、发生步骤、结果是否保存、用量是否未知和下一步。HTTP 状态不足以证明账号余额，无法确认的原因不猜测。失败的已有分析/计划/包不静默删除；新计划不恢复旧确认。

恢复动作须区分配置快照：替换同名环境变量中的密钥并重启后，旧任务仍引用该变量名，可在原状态允许且预算足够时手动重试分析；已用补丁计划仍需新版本确认。修改模型名、引用名称、超时或限额不会改变旧任务快照；需要使用这些新值时显式新建任务，提示新增费用与重复工作，不提供自动复制重试来绕过限额。仅修订计划继续使用原任务配置与累计预算。

## 7. 验证与交付

先用明确标 FIXTURE 的传输验证：缺失配置、revision 冲突、重复点击、任务/探测互斥、并发额度、UTC 跨日、用量未知、取消迟到结果、重启不重放、响应限制、鉴权/脱敏、配额和新表备份恢复。浏览器覆盖保存 → 本地诊断 → 费用提示 → 主动测试 → 刷新/失败提示，桌面与移动端。

再按 [验收与发布标准](验收与发布标准.md) 进行真实模型分析与补丁闭环；真实结果失败时保存原因，不能修改为夹具来过关。交付 M4 使用说明、递增迁移、检查结果与 evidence/M4 实际记录。无凭据时允许完成实现和夹具验证，但 M4 真实验收必须明确未执行。
