## 3. 真实联调样例

选择一个体量小、允许路径为既有 UTF-8/LF 普通文本且可人工理解的公开 Issue。可用新建的公开测试仓库，但必须标“自建测试场景”；上游真实 Issue 才可标真实贡献候选，不将两者混为贡献成果。避免为展示而上传私有源码。

1. 保存模型/限额，完成本地诊断与一次主动连接测试，记录 revision、时间、状态、耗时和用量，不保存凭据。
2. 从浏览器添加 Issue，读取固定 Commit 的有界源码；记录未读取内容、截断和其他数据缺口。历史成功的 GitHub 读取不能替代本次来源。
3. 发起真实分析，人工核对引文、来源和结论；记录误判与疑点。模型意见不当作事实，证据不足可停止并保留失败样例。
4. 保存明确计划和精确路径，核对 Commit/hash 后确认。修改计划验证旧确认失效，再确认实际使用版本。
5. 发起一次真实补丁生成，核对 Diff 静态检查、审核包和下载 hash。模型输出不合法应如实失败；修订新计划后重新调用需记录次数与用量，不构成自动修复循环。
6. 人工记录审阅意见；UNVERIFIED、application/compilation/tests=NOT_RUN 保留。应用不运行目标项目。外部人工验证如发生，在独立记录写环境/命令/结果，不把它混为应用自动检查。
7. 私有预览脱敏报告。公开真实报告由所有者选择；若不愿公开，用夹具验证发布权限/撤回，真实发布标未执行，不阻塞真实分析与补丁的联调结论。不得默认为用户发布。
8. 确认重启后任务、计划、包和用量保持。无 GitHub 写调用；若人工填 PR，标 MANUAL，不要求提交或合并 PR 作为验收条件。

最低正向目标是一条真实分析和一份合法真实模型审核包；失败输出不能算成功包。另保留至少一个真实失败/受限样例（例如自然发生的网络/限流/模型格式问题）；没有自然失败则使用受控夹具覆盖并明确来源，不刻意花费真实调用制造失败。

## 4. 云端与容量补验

环境记录实际 CPU/内存/磁盘、Linux/Node、应用 Commit、反向代理配置版本与限额。2核2GB 目标不能用 Windows 启动 RSS 或容器限制替代。

执行空闲 → 立即/定时发现 → 候选列表 → 人工选择/状态复核 → 来源 → 分析 → 补丁 → 下载 → 预览/发布/撤回流程，同时采样进程 RSS/生命周期峰值、整机可用内存、swap/OOM、磁盘/WAL、HTTP 状态及耗时。探针只做观察，需手工标注各阶段时间；供应商等待与应用响应分开记录。

初始容量判定：单活动任务无 OOM/崩溃/自动重放，任务与制品不丢；采样整机可用内存最低至少 256MiB；除供应商请求与管理维护操作外，健康/任务轮询/公开读取合计至少 100 次、p95 ≤ 1 秒，无意外 5xx。维护操作另记录最长阻塞，不以排除它掩盖故障。阈值是本次验收基线，不是持续 SLA；采样遗漏峰值、外部服务波动与小样本必须写入限制。不达标先收敛源码/上下文/限额，重测后再判定。

HTTPS 实测登录、Secure Cookie、CSRF、退出、私有下载；公网不可访问回环服务端口或数据库。演练服务停止/重启、中断不重放、备份校验、新路径恢复、会话清空、公开报告默认撤回与所有者重新发布。

## 5. 发布检查与证据模板

发布前核对域名、许可证（需要开源发布时）、供应商可用性与额度、私有配置、磁盘/日志配额、数据目录权限、备份与恢复路径。部署按运维文档构建；升级前停服务并备份，迁移先在副本验证；不可用旧程序直接读取不兼容新 schema。

证据放 evidence/M4/、evidence/M5/ 与 M3 后补记录中，仅在实际执行后创建通过结论。建议每条记录包含：日期/时区、Commit、环境、需求 ID、LIVE_API/FIXTURE、操作与输入引用、实际结果、脱敏制品/hash、耗时与 usage、未执行项和失败后的动作。费用未知写未知；不留原始凭据或原始供应商错误。

当前结论仍是 M0–M3 本地验证已有历史证据，M4-A/B 本地实现、M4-C 待真实验收、M5 待实现，真实模型、自动发现与云端容量待验收。本文件不改变该结论。

## 6. M5 自动发现验收矩阵（全部待执行）

| 场景 | 夹具应验证的结果 | 真实 GitHub/模型证据边界 |
|---|---|---|
| 手动发现 | 有效画像可立即发起；无模型只出规则候选；不读取 tree/blob、不创建分析 | 真实 GitHub 至少一轮，来源/ID/匹配字段可人工核实 |
| 定时/错过 | 虚拟时钟到期只入队一次；触发键去重；错过全跳过，下一未来时刻正常触发 | 真实 GitHub 至少一次通过正常调度触发的有界轮次；可暂用测试时刻，不将夹具时钟称真实调度 |
| 重复/增量 | 同页、重复轮次/重叠窗口不重复候选；重命名/转移稳定 ID；PARTIAL 不冒进水位 | 同一真实来源重复扫描核对候选 ID；搜索可能漂移，记录未完整窗口 |
| 忽略/收藏/排除 | 忽略后再扫不推荐，显式启用才恢复；收藏不解除忽略；仓库排除即时生效 | 真实候选管理持久化，不需 GitHub 写入 |
| 配置变化 | 版本冲突拒绝；新查询 fingerprint；旧轮快照保留；禁用评估/排除/忽略即时收紧 | 记录画像版本，不要求付费证明配置变化 |
| 限流/权限/超时 | 403/429、reset/Retry-After、缺失头、网络/5xx、分页截断；共享冷却释放槽，无无限重试 | 不故意耗尽 GitHub 配额；自然发生如实记录，否则夹具覆盖 |
| 预算耗尽 | 页/仓库/Issue/HTTP/字节/期限先到先停；模型耗尽不妨碍规则；UNKNOWN 不返还 | 真实 HTTP 计数和缺口；真实模型仅在另获调用授权且已启用后验收 |
| 重启/重复付费 | 网络/页事务前后中断；UNKNOWN、逻辑键防重；FAILED+已知 usage 也不跨轮自动重发；人工确认才新 attempt | 夹具不能证明供应商恰好计费一次；真实费用未知写未知 |
| 执行槽/取消 | 发现/分析/补丁/M4 探测并发触发，活动最多 1；FIFO/队列限额；迟到结果拒绝 | 观察正式进程；人工等待/冷却不持槽，不刻意并发付费 |
| 前置复核 | closed/已合并修复阻止模型；开放 PR/UNKNOWN 提示；确认过期重查、hash 变化失效 | 真实 Issue 及有限关联；未检出不等于无重复修复 |
| 安全/公开 | 游客不可读候选/画像；注入文本不执行；secret/私有路径不外泄 | 发现不自动发布报告，不因仓库公开就公开内部画像 |
| 备份/配额 | 全新表/水位/忽略/用量校验；恢复关定时/guard；旧备份迁移；配额满仍可取消/忽略 | Linux 另补真实恢复和资源观察 |

M5 规则发现的最小真实目标：立即与正常定时各一轮真实 GitHub 查询，至少一个稳定标识/来源链接可核实的规则候选，重复扫描和忽略持久验证，以及一次人工选择后的真实状态复核。若全部过滤或接口不可用，记录原因并保持真实验收未通过，不能以假候选补齐。适合度由人工评价，不设“必然可贡献”门槛。

可选模型关闭时记 NOT_RUN，可交付规则发现；开启分支须单独验证费用提示/启用记录、每轮每日预算、输入范围、结构化结果和 UNKNOWN/不重放。未执行真实评估不能称该分支联调通过，M4 真实分析不能替代发现评估证据。

浏览器覆盖画像保存 → 立即发现 → 运行详情/不完整提示 → 候选列表 → 忽略/启用/收藏/排除 → 选择 → 状态复核风险确认 → 既有分析入口，以及定时开关和配置冲突。覆盖桌面/移动端、刷新/重复点击；FIXTURE/LIVE_API 明确区分。未来证据存 evidence/M5/，不改变 evidence/M0–M3。

M3 云端补验增加发现最大配置下的 RSS/整机内存、SQLite/WAL、列表查询与排队等待；使用前述容量阈值，记录单轮限额触发。不通过先调低发现资源并重测，不能称新增发现沿用旧启动内存已适配。
